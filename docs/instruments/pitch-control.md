##### Reusable musical pitch and note control

Existing frequency modulation is linear Hz. Multiplying or adding the same Hz depth to several different-frequency oscillators does not generally preserve musical intervals. Keep all existing free/BPM timing, frequency ports, base values, connections and additive behavior compatible. Introduce shared pure pitch conversion and an explicit pitch-tracking mode or capability for pitched generators and resonators, with semantic modulation input measured in semitones (fine tuning in cents). Define one convention: `p=0` means the configured base tuning; `f = f_base * 2^(p/12)` for semitone offset p. Fine offsets can be fractional. A separate existing linear-Hz input is added after pitch scaling where supported; clamp the final physical frequency to its existing valid/sample-rate range. The order must be identical in DSP and prediction. Default pitch tracking off for existing patches; inactive connection/settings are retained with the conditional parameter system. Use shared parameter definitions, display mapping and live values, not a note-specific UI in each oscillator. Musical note names and optional Hz readout can be derived by a pure tuning utility; changing the tuning mode must not silently reinterpret previously saved Hz amounts.

Before typed note events are needed, expose a manual `Pitch Control` source with semitone and cents parameters and a single continuous semitone-offset output. Fan out to the new pitch inputs of any number of free-frequency oscillators or expose that control through a composite rack. A bank tuned to 110, 165 and 220 Hz becomes 220, 330 and 440 Hz at +12 semitones; all relative tuning survives without the extra buffering or resampling of Phase 6.20. Editing the shared control uses existing smoothed parameter updates and preserves oscillator phase. Keep connection units and range predictions explicit; provide a worked oscillator-bank patch and test independent pitch-control instances, octave/fifth ratios, nested fan-out, and legacy additive-Hz connections. No gate, trigger, keyboard or note-source implementation is required for this initial shared control.

**Implemented Phase 7.2.2.** `MusicalPitch` defines A4=440 Hz/MIDI 69, fractional semitone ratios and cent conversion. `PitchControlGenerator` (`generator.pitch-control`) emits one mono modulation signal `semitones + cents/100`, using standard smoothed controls (−48…+48 st, −100…+100 cents) and five built-in presets. On each oscillator select **Pitch tracking (free): Semitones**, then connect Pitch Control's Pitch output to its Pitch input with amount 1; repeat for all voices before summing their ordinary audio outputs in a Mixer. The amount is a multiplier of the source's numeric semitone signal, not the instantaneous transposition: amount 0.5 halves the offset and −1 inverts it. The oscillator's own Pitch offset adds to incoming contributions and clamps to ±60 st. `ParameterActivation` supports conjunctions of unconditional structural choices, so the socket and offset remain dormant when tracking is off or timing is BPM-synchronized. Schema-1 pre-pitch oscillators and presets receive zero/off defaults while preserving existing identities and Hz wiring. The Faust free-running phase integrates `clamp(baseHz * 2^(pitch/12) + additiveHz, 0.01, min(20000, 0.49*SR))`; enabling tracking is structural, but subsequent pitch edits preserve phase and never recompile. The estimator applies the same order using physical bounds (before audio-context sample-rate limiting), and the frequency control's passive meter reports actual shifted Hz. The configured cycle and period editor account for the local pitch ratio; live cycle uses measured effective Hz. The generator is always styled as a modulator, not an audio voice; it can be muted to neutral 0 st. The worked three-voice bank is generated by ordinary graph commands in `Orbit.Audio.Probe` and measured at 44.1/48 kHz; tests cover octave/fifth/cents, phase continuity, independent instances, nested rack routing and persistence. Future resonators reuse the same pitch convention when implemented. Implementation: [PR #6](https://github.com/wgabel/orbit2/pull/6).

After Phase 7.1 typed events, add a generic monophonic `NoteSource` or equivalent composable runtime sources. Store note/tuning/velocity configuration in the graph, but treat key press/release as transient actions. The first version implements a reference MIDI-note-number convention (A4 = 440 Hz, note 69) without requiring hardware MIDI: emit a held semitone offset `noteNumber - 69`, Gate, one-sample Trigger and velocity 0–1. Pitch and velocity use ordinary continuous modulation connections with explicit unit semantics; Gate/Trigger reuse the typed contracts. A single pitch source can drive multiple generators with different base frequencies and resonators with different ratios, preserving intervals. If one multi-output node requires compiler work, introduce general output-address lowering with per-instance state reuse and tests; do not duplicate the note state machine in independent DSP emitters. Begin with an accessible on-screen keyboard/manual note action and clearly defined last-note priority, repeated note, legato/retrigger and key-release rules. Optional hardware MIDI is a separate browser input adapter using the same application event contract, not a Domain dependency.

~~~mermaid
flowchart TD
    K[Keyboard or sequencer] --> N[Note source]
    N -->|Pitch offset| S[Pitched oscillator bank]
    N -->|Gate or trigger| E[Shared envelope]
    N -->|Velocity| G[Gain or excitation]
    E --> G
    S --> G
    G --> O[Audio output]
~~~

Runtime note actions are generation-qualified and scheduled on the shared sample timeline, following Phase 7.1 event delivery. Do not rebuild or recompile the graph for notes, change persisted base settings, or record note-on/off in graph undo history. Pitch/velocity update coherently with gate/trigger on the intended sample; stop, navigation/runtime replacement, losing input focus or disconnection must not leave a stuck gate. Reject stale events and bound queues. Keep a held note's sound stable across ordinary parameter edits; failed structural replacements retain the last-good runtime. Test note-to-Hz mapping, exact octaves, harmonic ratios under vibrato, monotonic pitch modulation, conditional connections and accurate range estimation. Full polyphonic note allocation is deferred until monophonic performance is reliable.

### Phase 7.2.3 — Note Source (in review)

Add **Note Source** from Add node. This is a control source, not an audio generator. Select it, play the connected patch, and choose **Arm keyboard**. Use A–K / W E T Y U or hold the on-screen piano keys; Z/X change octave. The reference note maps to zero semitones (A4 by default; choose A3 for a 220 Hz bank). Keyboard velocity is a fixed editable 0–1 value, default .8, captured at note-on and quantized to 127 steps. The five presets provide useful reference notes and soft/full strikes. No hardware MIDI is required.

| Output | Signal type | Meaning |
|---|---|---|
| Pitch | Modulation | Held semitone offset from reference, bounded ±60; starts at zero |
| Gate | Gate | 1 while a key is held, 0 after final release |
| Trigger | Trigger | One sample of 1 on each new note-on; no pulse on fallback |
| Velocity | Modulation | Last active note's strike strength 0–1; retained after release for tails |

**Try a modal handpan:** connect Note Source Pitch to Modal — Handpan Pitch (st), Trigger to Trigger, and Handpan Audio to Master output. Select A3 reference and play. For direct velocity, open the composite and set the internal Gain connected to Strength offset to base 0 instead of .75; connect Velocity to Strength offset at unity. A new note can retune an existing resonant tail because this is monophonic. For a sustained oscillator voice, set free pitch tracking to Semitones, wire Pitch to Pitch, Gate to an ADSR Envelope's Gate, and Envelope to oscillator amplitude (base zero). Use a separate Gain stage (base zero) modulated by Velocity if velocity-sensitive loudness is desired. See [physical modelling](physical-modelling.md) and [envelopes](../audio/envelopes.md).

Last pressed note wins. Pressing another key updates pitch/velocity and emits a trigger without dropping Gate, so a gated ADSR continues legato; choose Trigger-driven AD for independent attacks. Releasing a nonactive key does nothing; releasing the active key restores the most recent held key and its previous velocity without a trigger. Final release closes Gate but holds Pitch/Velocity, allowing tails and releases. Repeated note-on retriggers; browser key-repeat is ignored. Release all notes, disarming, losing window focus/visibility and leaving the selected node release the gate. Stop/replacement discards held state (no reseeding of gated notes, unlike continuous Note Sequencer), so re-press a note after topology replacement. Ordinary parameter edits do not recompile or reset held keys. Accessibility click activation sends a short strike; pointer press/release supports held notes.

The existing generation-qualified performance contract now carries velocity and distinguishes a note action lane from a continuous-pitch lane. A bounded AudioWorklet queue resolves last-note priority using fixed-size storage; admission is bounded, and overload prioritizes release/reset over stale note-ons. One packed word represents a pitch/velocity/trigger update at a sample, while the compiled Faust tuple provides distinct output addresses with shared state and one action input per source. Mute shares one control across outputs; gate/trigger are binary, continuous outputs slew. Per-port range estimation and signal taps work through nested rack routes. Events do not modify graph history or persistence. Tests cover host action routing, note priority, saturation, and exact compiled output samples at 44.1/48 kHz. Browser latency, MIDI, note-pattern articulation and polyphony remain follow-ups.
