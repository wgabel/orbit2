##### Keyboard performance and continuous pitch sequencer (Phase 7.2.8 — partial)

**Implemented 7.2.8a — live continuous pitch.** Add **Note Sequencer** (`generator.note-sequencer`), set its Reference note (default A4/MIDI 69), and connect its Pitch output at unity to the Pitch sockets of free oscillators with Semitones tracking enabled. For a bank tuned around 110 Hz, set A2/MIDI 45 as reference; the A2 key is unison and A3 doubles all tracked base frequencies. Initial pitch (default 0 st) applies before the first key and after Reset pitch. Select the node header to automatically open the shared piano dock. The on-screen piano and physical A S D F G H J K / W E T Y U keys share a validated note-on/off contract; Z/X change octave. The octave and available keys respect MIDI 0–127 and the receiving ±60 st offset range. Key release never resets the latch. Text/slider/select editing, dialogs, modifiers, auto-repeat and disarmed input are excluded. Selecting another compatible node retargets the dock; ordinary graph selection and navigation retain it while present. Collapsing pauses capture; stopping resets transient input state. Blur/visibility loss clears held codes without resetting pitch. See [persistent piano dock](pitch-control.md#phase-723--note-source-in-review) ([PR #70](https://github.com/wgabel/orbit2/pull/70), in review). The live offset is measured from the current DSP meter, not guessed from the last UI key. Five reference/starting-offset presets use the ordinary catalog and persistence; no transient target or octave state is serialized. Implementation: [PR #16](https://github.com/wgabel/orbit2/pull/16).

Each reachable Note Sequencer reserves one lane in the existing bounded manual action worklet manifest (30 combined sources, 64 queued commands per lane). Values 1–128 encode MIDI note + 1, 129 explicitly resets to Initial pitch, and zero is no event. The Faust evaluator latches note number at the action sample, emits `clamp(note - reference, -60, 60)` or Initial pitch, and reports a passive graph-qualified pitch meter. MIDI note-on actions reject out-of-range, disconnected, stale, inactive or busy targets; note-off is a no-op in this mode. The host preserves accepted pitch codes for compatible reachable nodes across structural voice replacement by seeding the new worklet lane before its first render; removal or root stop retires that transient state. Ordinary note changes do not modify the editable graph, revision, history, base parameters, playback generation or oscillator phases/effect state. Host-message latency is not scheduled sample accuracy; accepted internal action transitions are sample-aligned. Quantized live recording is implemented in the 7.2.8c PR below; Note-mode articulation was implemented in 7.2.8d. That initial 7.2.8a implementation had no Gate/Trigger outputs; 7.2.8d adds them below.

**Implemented 7.2.8b — pitch patterns, long transport and glide.** Select the Note Sequencer and open **Edit pattern**. Choose Live or Loop, 1–64 steps (default 16), synchronized quarter-beat divisions multiplied by 1–64, or Free seconds (0.01–600 seconds per step). Glide is a linear semitone ramp, 0–600 seconds, sampled at a new pitch target; an interrupted ramp retargets from its current value. The grid keeps the edit cursor distinct from the measured playhead. Select a slot and choose a MIDI note or Hold; optionally enable Step entry and show the keyboard to enter notes and advance by 1, 2, 4 or 8 slots. Space enters Hold; arrows move the cursor; wrap is automatic. Shrinking retains hidden slots. Clear all requires confirmation and is one undoable graph command. The slow-drone and quarter-note pattern presets are ordinary named node configurations. Implementation: [PR #17](https://github.com/wgabel/orbit2/pull/17).

The schema-1 fixed-capacity payload uses stable keys `pattern-step-01` through `pattern-step-64`, zero = Hold, 1–128 = MIDI + 1, and bounded timing/count/glide/mode controls. Complete pre-pattern sequencer patches and presets migrate to Live and 64 Holds without changing existing IDs. Imports with malformed or missing partial slot data are rejected. Pitch values remain clamped relative to the current reference. Pattern controls are not duplicated as 64 sliders in the node frame. Runtime pattern values are immutable snapshots sent as a single lane update at the next render quantum, not Faust structural controls. The scheduler evaluates the current slot on activation, timing/mode edit, reset or seek, looking back to the most recent populated step when applicable instead of replaying missed events. Slot-only edits (including a committed take) become active at subsequent step boundaries, rather than replaying the onset of the current step. Ordinary Holds emit a playhead update without a pitch change. Live keyboard input can override a running loop until the next populated step; switching Loop to Live holds the last pitch.

The existing transport worklet now additionally publishes split whole/fraction beat and elapsed-second positions plus reset identity, preserving the original wrapped phase and reset channels for legacy nodes. Both loop modes anchor to transport zero, freeze/resume with root playback, and reset to step one on Reset transport. Tempo changes do not affect elapsed seconds; synchronized loops preserve musical position. The action adapter consumes the extra clock channels internally, keeping the original 30-lane and 32-channel DSP limits. Its scheduler sends combined integer step/note codes (step × 256 + action, step 65 denotes Live) to the Faust latch, which reports a measured 1-based playhead and ramped offset. Timing uses double-precision modulo across split positions; whole-position channels are exact up to 2^24 beats or seconds. Full patterns are applied without graph compilation or carrier phase restart. A replacement derives the active nonempty pitch from the shared clock; arbitrary DSP state transfer across structural replacement is not promised.

**Implemented 7.2.8c — quantized live recording.** Select the Note Sequencer, open Edit pattern, choose Loop and a step count/timing, play the connected patch, show the keyboard and disable Step entry. Choose Overdub (retain existing slots) or Replace active slots (start with Holds; retain hidden slots) and a quantization spacing that divides the active step count. Record take creates a transient `PitchRecordingTake`; the pending grid previews notes while normal live pitch monitoring continues. Each admitted note-on reads a fresh running audio-clock transport position through `IMusicalTransportService.ReadPlayingPositionAsync`, independent of UI telemetry, and only accepted performance actions are recorded. This timestamps host admission, not the exact physical strike or the rendered sample. Nearest compatible boundary wins, ties go forward, wrap is modulo the loop, and later accepted note-ons replace earlier notes in the same slot. Free patterns use elapsed seconds; synchronized patterns use beats, including long loops and tempo edits. No release inserts a Hold. Reset/clock replacement, pattern/reference changes, target change, dock collapse or playback stop invalidate the take. Commit take verifies the original pattern/reference and live transport generation, then issues one existing `SetPitchPatternStepsCommand`; Cancel discards only the draft and never rewinds audible live pitch. The pending take is not passed to the worklet, autosaved or added to graph history. Committed slot changes take effect at future step boundaries; there is no overdue-note replay or per-note compilation. Undo/redo and patch export/import reuse the ordinary pattern persistence contract. Implementation: [PR #19](https://github.com/wgabel/orbit2/pull/19).

**Implemented — 7.2.8d playable note sequencing and focused editing ([PR #87](https://github.com/wgabel/orbit2/pull/87)).** The sequencer now offers a selectable **Playback** value: **Pitch only (drone)** (default, preserving prior behavior) or **Notes (gate + trigger)**. Both keep the original `pitch-out` identity. The extra typed outputs are `gate-out` (Gate), `trigger-out` (Trigger), and `velocity-out` (continuous 0–1). In Notes mode, stored note codes 1–128 trigger an attack and hold a gate; code 0 ties the previous gate into the next step, while explicit code 129 is a **Rest** that closes it. A single pattern-wide Note length fraction (0.05–1, default 0.9) determines a release near the end of the last note/tie step. The audible Velocity control (default 0.8) remains pattern-wide until S2; saved per-note overrides are CI verified below, awaiting merge. The current monophonic representation cannot store simultaneous pitches; independent gate length overrides are implemented below. Pitch-only mode ignores Rest as a pitch update. All new controls default to pitch-only when restoring old schema-1 patches, and old reference/pattern presets migrate without discarding existing data.

**Editing interaction.** Select a Note Sequencer to activate the shared bottom piano, then choose **Edit pattern**. The melody editor floats above the dock instead of permanently increasing its height. **Edit notes** exposes a pitch/time grid (tap/click a cell to insert or remove a note), a horizontal step strip, a focused step note picker, Tie/Hold, Rest, and auto-advance. Pressing the physical or screen piano while the editor is in Edit notes places the note and advances without requiring a second arm checkbox. Use octave arrows over the grid to inspect higher or lower pitches, and Z/X in the shared keyboard to change keyboard octave. **Record** contains Overdub/Replace, quantization, and Commit/Cancel take. **Settings** contains timing, glide, note length, velocity, and reference pitch. Pattern playback still uses the patch-level **Play patch** transport; selecting Loop is necessary before recording a take. The compact canvas node previews at most the first 16 steps and indicates continuous vs Notes playback. Drag-to-resize/reposition and per-note velocity remain future refinements; the note grid is click/tap driven.

**7.2.8-S1 — Independent note lengths (merged, [PR #111](https://github.com/wgabel/orbit2/pull/111)).** In Notes mode, select a populated step in Edit notes and enter Note length (0 = default). An explicit fraction above zero up to 1 specifies the sounding fraction of a step; consecutive Tie slots extend the note through the full preceding steps, and the onset's fraction is applied to the final tied step. E.g. a one-beat note at 0.25 sounds for a quarter beat; the same note followed by one Tie sounds for 1.25 beats. A value of 0 inherits the pattern-wide Note length. The override is a gate duration, not a change to the transport grid or a guarantee of acoustic sustain (one-shot Trigger instruments still use their own decay). 

Schema-1 adds 64 non-modulatable fixed keys `pattern-step-gate-length-01` through `pattern-step-gate-length-64`. Existing complete patterns and presets migrate to zero overrides; malformed partial override arrays are rejected. Values are saved by slot, including inactive slots, and retained when replacing notes, recording pitch or clearing notes; edit a populated slot to reset its override. The worklet receives the bounded `gateFractions` array with the existing pattern snapshot; explicit length is latched at note onset and inherited through ties, so changing it does not retrigger the current note. Legacy default length behavior remains unchanged. No new output, gesture, polyphony or per-note compilation is introduced.

**7.2.8-S1 — Per-note velocity data (CI verified; awaiting merge, [PR #113](https://github.com/wgabel/orbit2/pull/113)).** Schema-1 adds 64 non-modulatable, nonstructural keys `pattern-step-velocity-01` through `pattern-step-velocity-64`. Stored values are -1 (inherit the pattern-wide Velocity) or a normalized value from 0 to 1 in hundredth increments; zero explicitly means zero strength, not default or Rest. The shared domain choices reject other values, including negative fractions, non-finite values and incomplete override families. Existing patches and presets missing the entire family migrate to -1 without changing their original IDs, duration overrides or settings. Values are stored by slot, retained across shrinking, pitch replacement and recording, and included in the immutable `PitchPattern.VelocityOverrides` snapshot and ordinary parameter undo/redo. No change to note ordering or overlap: an onset occupies one slot, and Tie extends the preceding onset. S2 will consume only onset-slot velocity, keep it through ties, and use the pattern default for inherited notes; pitch-only behavior and live keyboard behavior are unchanged in this data increment. The override currently has no audible effect and no dedicated editor control; these are S2/S3 work.

**Connections.** For Physical Pluck/Marimba connect sequencer Pitch → Pitch and Trigger → Trigger, then Audio → Master (set instrument gain conservatively). For Clarinet/Flute connect Pitch → Pitch, Gate → Gate and Audio → Master. With the sequencer set to Notes + Loop, the instrument plays the programmed melody **without a separate Note Source**. Set Velocity → instrument Strength or Expression (and the destination's base to zero) if desired. This may be ignored or produce no sound until the target audio graph is reachable; an unconnected Pitch alone cannot excite a plucked instrument. The Edit notes panel reports missing Pitch and Gate/Trigger cables; it does not claim the downstream instrument or patch playback is audible. Pitch-only drones do not implicitly send gate or trigger.

**Worked live take.** Route the sequencer Pitch at unity to the three pitch-tracked oscillators of the slow-drone example below. Set reference A2, 16 steps, a quarter-beat step and quantization every four steps; choose Replace active slots, start playback and Record take. Play A2, D3, E3 and A2 near the four beat boundaries, then Commit take. The resulting four occupied slots are 1, 5, 9 and 13; the intervening Holds preserve pitch. For a four-step ambient take, use Free 20 seconds, quantization every step and 4-second glide. Switch to Overdub to replace individual notes in a subsequent pass. Cancel is safe and Undo restores the entire previous committed pattern. Optional count-in/metronome, recording note durations, finer onset editing and per-note velocity remain future work; Notes-mode Gate and Trigger articulation is implemented.
