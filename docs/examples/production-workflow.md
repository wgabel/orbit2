# Music creation: end-to-end production workflow

[Music creation](README.md) · [Task index](task-index.md) · [Foundation catalogue](foundations/catalogue.md)

## End-to-end workflow

**Mandatory whole-piece acceptance:** Use the [musical composition validation protocol](musical-composition-validation.md) from planning through delivery. Define role-by-section expectations before building; audit actual material and routing, seek a native render and measure audible roles in context, correct failed criteria and re-render when possible. The protocol owns gate statuses and the evidence required for a finished composition; this workflow routes to the detailed techniques. A missing render or audition must be explicitly labeled as unverified, not passed.

**Score planning for pitched music:** Before constructing the patch, consult [harmony, scales and temperament](harmony-scales-and-temperament.md) and [classical composition and melody](classical-composition-and-melody.md). Plan actual notes and durations, tonal/modal choices, chord voicings/bass, intentional dissonance, motif, phrase goals and contrasting sections. Consider a keyboard-like reduction and develop the idea before choosing orchestration. These tools also serve pop, chip, ambient and other styles; select what fits the intent, never enforce historical tonal conventions indiscriminately. Use the worked examples as exercises, not validated patches.

**Form and material before graph construction:** for whole pieces, use [compositional development](compositional-development.md) to choose a recognizable identity, plan how it is developed at phrase and section timescales, and allocate musical attention. Keep a compact section plan with intended time/bar boundaries, actual material, active roles, contrast and transitions. A short loop, sound effect or deliberately static texture need not have a song form. For cinematic/orchestral work, use the [cinematic composition and orchestration guide](genres/cinematic-orchestration.md) to develop a score reduction into expressive instrumental roles and a complete cue. Its proposed patterns are exercises, not prevalidated Orbit patches.

**Sound palette planning:** before constructing a new musical patch or individual synthesized voice, consult the [synthesizer patch recipes](synthesizer-patch-recipes.md#use-the-recipes-when-creating-music-in-orbit-2). Select or adapt suitable techniques for the important voices, or explain why a different design better serves the brief. Translate the settings using current node contracts, and evaluate the resulting voices using the existing production loop.

**Current instrument selection:** after the score/roles are known but *before* building every voice from oscillators, inspect the [role-to-instrument decision table](instrument-recipes.md#choose-an-instrument-for-the-musical-role). Compare an appropriate existing physical instrument, instrument composite and/or synthetic recipe for each important part. Check Pitch/Gate/Trigger/Velocity wiring, native range, monophony and experimental limitations. Use [actual instrument usage](../usage/sound-and-instruments.md#faust-instrument-nodes) for patch connections. A physical model is a candidate, not automatic acoustic realism; a deliberately synthetic sound may be the right choice.

**Instrument audition:** for any genre whenever individual sounds need development or comparison, use the [fixed test melody and protocol](instrument-design-and-audition.md#3-the-instrument-audition-fixture--test-melody-driver-v1). Choose a suitable fixed profile (melody, sustained drone, percussion, chord or audio-input test). Test alternatives with identical relevant performance controls and matched levels, then in a representative mix. Preserve the original score when it has already received positive feedback. A native render is not listener approval; record distinct evidence before recommending a sound.

For complete pieces and substantial voice design, use the [detailed production iteration](mixing-mastering-and-analysis.md#5-agent-workflow-render--analyze--refine--re-render) alongside the [musical quality checklist](music-theory-and-sound-design.md#11-agent-workflow-and-quality-checks). These guides own the measurement and creative techniques; the validation protocol owns acceptance. The following is a routing summary.

Refinement is part of creative work, not just a final checklist. A valid graph is not proof of good music. Scale the loop to the task: a small effect may need one representative input and a few checks; a three-minute composition should be considered over its musical form. If native rendering, measurement or listening is unavailable, continue with what is feasible, distinguish approximations from verified results, and state pending checks. Do not invent a measurement or a listening verdict. There is no required genre, node count, foundation, numeric loudness target or number of iterations.

## Documentation feedback and knowledge retention

- Before proposing new musical guidance, check this index, the relevant linked section(s) and the existing foundation catalogue for overlapping work. Improve the existing source of knowledge; do not create a second competing workflow.
- Keep this index short and route by task or decision, including new topics that do not yet fit existing categories. Add focused guides when the knowledge merits its own module; link them here and from related documents. Preserve historical examples and actual PR provenance.
- When a run reveals a useful general principle, record the evidence and scope in the appropriate existing guide. For a reproducible, distinctive sound relationship, follow the [foundation maintenance process](foundations/catalogue.md#maintaining-and-expanding-the-catalogue). An ordinary patch request does not automatically authorize publishing private material or modifying the repository; report useful candidates for later inclusion if outside the current task scope.
- For a supplied tutorial, transcript, article or other external learning source, follow [music learning source intake](music-learning-sources.md). Synthesize explanatory, reusable techniques in their existing authoritative topic guides. Do not place full third-party transcripts in the routine agent context or assert Orbit/listener validation from a tutorial alone.

- On handoff, report documents actually consulted, information that was hard to find, what was verified, and what new knowledge was added or should be added. Keep the workflow adaptable to new creative and technical methods.
