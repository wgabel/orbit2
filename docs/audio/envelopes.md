#### Envelope generators and rhythmic triggers (Phase 7.1 — partial)

**Status:** 7.1.1 AD envelope, 7.1.2 typed ports/adapters, 7.1.3 rhythmic sources (PR #10), 7.1.4 AR/ADSR/Loop (PR #12) and 7.1.5 envelope visualization implemented; custom envelopes planned. AD presets, an impact composite and initial AR/ADSR/Loop presets are implemented; additional envelope presets and worked patches (7.1.6) remain partial.

**Purpose and boundaries.** Introduce one registered `EnvelopeGenerator` (`generator.envelope`) with a unipolar modulation output (0–1 by default). It generates a time-dependent control signal, not a sound oscillator, and is independent of its destinations. It can drive amplitude, linear-Hz frequency, filter cutoff, gain, effect mix or any other compatible parameter; the target retains its own units, clamp and modulation depth. Do not embed a separate envelope implementation in every oscillator or effect. This is unrelated to the existing browser `AudioEnvelope`, which manages playback voice fades and graph replacements.

**Start with existing oscillators.** An oscillator already provides a repeatable waveform at free Hz or a shared BPM division. The first AD implementation needs only a dedicated mono continuous input, `Signal trigger`, accepting Audio or Modulation signals through the current compatibility rules. Use a shared sample-rate edge detector (Schmitt thresholds initially high 0.1, low 0.0); a low sample arms it and crossing the high threshold emits one rising-edge event. Continuous high values do not retrigger; a disconnected input is inactive. The detector initializes unarmed, so a new graph starting with an already-high input does not create a phantom hit. A square oscillator is the simplest source; sine and triangle work too. The detector sees the weighted input, so use a unity connection by default. The input is single-source, distinct from parameter sockets. The later typed-event implementation must retain this working oscillator input and its saved wiring, not require users to rebuild patches.

**Envelope shapes.** Implement a single DSP state machine with selectable modes, shared segment evaluation and stable parameter identities. Modes are discrete settings; retain dormant parameter values/connections through mode changes using the existing activation system. An AD trigger runs to completion independently of input high duration. AR and ADSR use gate duration; Loop repeats the AD trajectory with an optional rest, and Custom later supports a validated, bounded sequence of user-edited points. Do not require custom point editing for the initial node.

| Mode | Stages and behavior | Typical use |
|---|---|---|
| AD | Attack to 1, decay to 0, then idle until the next rising edge | Drums, impacts, transient pitch sweeps |
| AR | Attack to 1, hold until gate falls, release to 0 | Swells and gated textures |
| ADSR | Attack to 1, decay to sustain, hold while gate is high, release on gate fall from any stage | Notes and instrument articulations |
| Loop | Repeat completed AD segments with optional rest while enabled | Repetitive LFO-like shaped modulation |
| Custom (later) | Bounded list of timed, shaped segments with explicit end/loop behavior | Complex automation |

    Idle --> Attack: Rising trigger
    Attack --> Decay: Attack complete
    Attack --> Sustain: AR attack complete
    Decay --> Idle: AD complete
    Decay --> Sustain: ADSR decay complete

    Decay --> Release: Gate falls in gated mode
    Release --> Idle: Release complete

    Release --> Attack: Retrigger
    Sustain --> Attack: Retrigger

**Parameters and continuity.** Attack, decay and release are durations (milliseconds, using actual sample rate); sustain is a level, not a duration. Provide a short nonzero default attack (e.g. 8 ms), adjustable duration up to multi-second swells, and bounded linear/exponential-style curves that reach their exact endpoints. A zero-duration stage may be supported deliberately for control-only transients; it can cause clicks when used on amplitude, and looping must never spin through zero-time stages. Support continuous parameter modulation where meaningful: latch effective segment duration/curve at segment entry for deterministic timing, and smooth changes to a held sustain level. Later consider explicitly specified in-flight time warping rather than letting slider changes discontinuously reposition progress. Retrigger from the instantaneous output, not a forced zero; early gate-off releases from the current value. No implicit reset on ordinary base edits or visualization. Test an explicit overlap/retrigger policy, including rapid events and gate release; do not promise click-free output for arbitrary downstream modulation/overdrive or DSP topology replacements.

**Worked impact patch.** One existing square oscillator at 1 Hz (or half-note at 120 BPM) feeds two AD envelopes. The pitch AD has 1 ms attack and 120 ms decay, with an approximately exponential decay; the amplitude AD has 8 ms attack and 500 ms decay. Connect pitch to the audio oscillator's free Frequency with depth 300 Hz and base 55 Hz; effective frequency sweeps from 355 Hz to 55 Hz. Connect amplitude with depth 0.8 and base 0. A third independent AD may control filtered noise amplitude or cutoff. Combine lanes through a mixer with sufficient headroom; use the scope to check peak levels and avoid confusing clipping with envelope discontinuities. The amplitude smooths the start while the shorter pitch sweep gives the transient its character. The graph requires no change to existing oscillator code.

**Implemented Phase 7.1.1.** Add **AD Envelope** from the node catalog or use the editable **Impact — AD percussion** composite and connect its Audio output to Master output. The envelope has independent Attack (1–10000 ms), Decay (1–20000 ms), Attack curve and Decay curve (0.25–8, where 1 is linear). Defaults are 8 ms, 500 ms, 1 and 3; larger decay exponents fall more quickly, larger attack exponents start more slowly. All four are ordinary modulatable controls with the shared parameter editor, preset system and signal scope. `FaustSchmittEdge` implements the detector; `FaustEnvelopeSegments` holds per-instance state and evaluates normalized power curves. On the event sample, preserve the previous output and latch attack controls; after N = max(1, round(ms × sample rate / 1000)) further samples reach exactly 1, latch decay controls, and after D further samples reach exactly 0. A retrigger takes priority over stage completion. Falling edges never interrupt AD. The node conservatively predicts 0–1 for destinations, uses the ordinary signal weighting rules, and base edits do not rebuild the Faust program. The composite and five node presets are regular editable, persistable graphs/configurations; dedicated envelope visualization, other modes, and typed event sources remain later phases. Implementation: [PR #7](https://github.com/wgabel/orbit2/pull/7).

**Explicit rhythmic infrastructure (Phase 7.1.2 and later).** Trigger, Gate and Clock have reusable typed routing contracts. Phase 7.1.3 adds manual and transport-clock sources:

| Source / adapter | Meaning | First consumer(s) |
|---|---|---|
| Signal-to-trigger adapter | One-sample pulse on a qualified rising edge (shared detector above) | Envelope, sequencer, sample restart |
| Manual Trigger | One pulse per accepted runtime action; no persisted pressed state | Audition one-shots, trigger fan-out |
| Gate | Normalized 0/1 level; timed manual opening or typed Trigger/Clock input; rising activates, falling releases | AD, AR/ADSR, gated playback |
| Clock | One timing pulse per rhythmic boundary, free Hz or transport-synchronized musical division | Envelopes, gates, steps and sample playback |

Use scalar per-sample streams internally (event pulse 1 for exactly one sample, 0 otherwise; gate 0/1), with typed ports enforcing intent. Keep signal-to-event conversion explicit; do not treat arbitrary positive audio as a typed trigger or permit event streams to be multiplied by ordinary audio gain/modulation depth. Typed event links have unity semantics and single-source input policy; fan-out is supported. Multiple events may later combine through an explicit merge/logic adapter, with coincident pulses coalesced by a documented policy. Add conditional source selection or a separate typed input alongside the existing oscillator input, with a single active source and retained dormant connections. Phase 7.1 must extend graph validation, connection editing, rack mirroring/flattening, dependency ordering, persistence, range/observation handling and shared port rendering (triangle Trigger, square Gate, hexagon Clock) consistently. Test nested fan-out without duplicate or delayed events; add multi-output compiler support only when a node actually needs it. Mute on event/gate sources must suppress pulses or close the gate rather than slew a boolean through fractional values.

**Implemented Phase 7.1.2.** `Signal to Trigger` and `Signal to Gate` use the same 0.1/0.0 Schmitt thresholds on their weighted mono continuous input. Trigger starts unarmed, emits a single sample on each qualified rise and never synthesizes a startup-high pulse; Gate starts closed, opens at high (including startup high), holds in the deadband and closes at low. AD now exposes a structural Trigger source choice: Continuous signal (legacy/default), Trigger / clock (binary pulses consumed directly), or Gate rising edge (the existing Schmitt detector; falling does not release AD). All three sockets keep distinct identities and dormant wires. Schema-1 AD documents and presets get only the new identities/default selector; existing wires and values remain unchanged. Event ports are mono and single-source, Clock-to-Trigger is the only cross-event compatibility, event amounts are exactly 1 on connect/edit/restore, and composite racks mirror the same constraints. Faust routes events without gain arithmetic or delay, scopes can observe binary streams, and mixed-output composites reuse the same mute control while continuous outputs ramp and events switch immediately. Muting a Gate closes it; unmuting while high restores its level, while Trigger never replays missed events. Event badges display the type and the inspector has no amount field. The compiled tests measure exact fan-out/rack alignment, Schmitt transitions and mute behavior at 44.1/48 kHz. Clock generation and manual actions build on these contracts in Phase 7.1.3; AR/ADSR gate release remains 7.1.4. Implementation: [PR #8](https://github.com/wgabel/orbit2/pull/8).

**Implemented Phase 7.1.3.** Manual Trigger exposes a Fire trigger button; Gate defaults to Manual with Open gate and Close gate buttons, or can select Trigger / clock and accept a unity typed input. Gate duration is a modulatable 1–20000 ms control (default 100 ms). An open/retrigger latches the effective duration and emits 1 for exactly max(1, round(ms × sample rate / 1000)) samples including the action sample; retrigger replaces the remaining duration, Close forces zero immediately, and idle is zero. Clock defaults to Synchronized (BPM), using the existing musical division choices and shared audio-clock transport; Free (Hz) integrates its modulatable 0.01–100 Hz rate with fixed-point phase. Each clock emits a single sample per crossed boundary, not on DSP initialization, transport reset/resume, or division change itself. The transport exposes an additional reset marker channel only when a synchronized clock needs it; the 12-beat phase wrap is a normal boundary. Frozen transport produces no pulses and live tempo changes follow the shared phase. The five Clock and Gate presets use the ordinary parameter system. Implementation: [PR #10](https://github.com/wgabel/orbit2/pull/10).

Manual actions are transient, addressed by patch, owning graph and node ID; disconnected or dormant sources, inactive playback, stale/replacing generations and full queues reject actions. The compiler exposes a deterministic reachable-source manifest (up to 30 manual lanes) after the optional beat/reset inputs; one generation-owned AudioWorklet bridge per voice forwards transport channels and consumes fixed FIFO queues of up to 64 pending actions per lane. Commands are separated by a zero sample, so rapid clicks cannot collapse into one event; accepted Fire and Close commands enter the next available render quantum, with browser message-delivery latency, rather than a UI-rate timer. Retirement/stop clears pending events and new voices start idle. No manual action changes parameters, graph revision, undo history, persisted data or compiled source. Typed fan-out and nested racks consume the same sample stream; gate mute closes the routed output and suppresses trigger pulses without replay. Held-key gates and keyboard note events are separate future functionality. The offline compiled and browser tests exercise exact pulses, retriggers, gate duration, transport boundaries, queue limits and generation lifetime at supported sample rates.

**Implemented Phase 7.1.4.** The catalog's **Envelope** node (previously AD Envelope) retains `generator.envelope` and all existing parameter/socket IDs. Mode is a structural choice (AD default, AR, ADSR, Loop); AD retains its three trigger-source choices and prior timing. AR and ADSR activate the existing typed Gate input directly regardless of the dormant AD trigger selection. An oscillator can provide a gate through Signal to Gate; a Clock or Manual Trigger can drive a timed Gate. AR exposes attack/release and their curves, ADSR also exposes decay/curve and sustain (normalized 0–1), and Loop exposes attack/decay/curves plus a 0–20000 ms rest. Release defaults to 500 ms, release curve 3, sustain 0.5, rest zero. Release is bounded to 1–20000 ms; attack/decay preserve their original limits. Loop begins at the first DSP sample and repeats attack–decay–rest while playback runs; it requires no trigger and continues its internal phase when muted. Rest zero adds no extra sample. All numeric settings are ordinary modulatable controls; inactive controls and their wires are retained but excluded from dependency lowering. The shared activation system supports guarded conjunctions and alternatives over structural choices, preserving the original graph/preset/history contracts. Complete schema-1 AD documents and presets (both pre-typed and typed) migrate to AD with new default values and identities only for the newly added controls. Three initial examples (Gated swell, Held voice, Breathing loop) complement the existing five AD presets; larger worked patches remain Phase 7.1.6. Implementation: [PR #12](https://github.com/wgabel/orbit2/pull/12).

`FaustEnvelopeSegments` now shares one seven-value recursive state machine (stage, elapsed, start, target, duration, curve, level) among all four modes. Gated modes respond to both typed rising and falling transitions, including a high gate on the first sample; a disconnected/low gate is idle. On a rise, let attack start from the previous sample; on a fall in attack, decay or hold, preserve the instantaneous level and begin release. Events take priority over simultaneous segment completions. Attack reaches exactly 1; AR holds 1, ADSR decay reaches the sustain level latched at decay entry, then holds and tracks live sustain with a bounded 10 ms full-range slew. A release reaches exactly 0 and retrigger from release starts from its actual level. Durations/curves latch at segment entry and each positive duration rounds to the nearest sample (at least one). Loop rest latches at decay completion, and its next attack latches at the rest endpoint. New modes initialize smoothed base controls from the actual configured value before applying ordinary smoothing to subsequent edits, so the first stage/loop uses the intended settings; AD preserves the legacy control path. Numeric edits do not replace the running voice; mode changes use the ordinary structural crossfade and reset state. Compiled tests at 44.1/48 kHz cover both old AD behavior and gate-off at stage boundaries, rapid retrigger, decay target latching, smooth sustain, exact loop/rest and typed gate fan-out. Domain tests cover dormant routing, identity migration and ordinary history; published editor smoke covers live mode transitions.

**Timing and host commands.** The shared sample clock owns all state transitions. Free clocks integrate phase; BPM clocks use the existing shared transport beat/division, including nested graphs and live tempo changes. Detect each rhythmic crossing once, accounting for the transport's 12-beat wrap/reset and pause/resume; document the first-pulse and missed-boundary behavior rather than replaying missed beats. A pulse fanned out to multiple consumers is shared on the same render sample. Manual trigger and gate actions are transient, graph-qualified runtime requests with accepted generation checks, not `SetParameterValueCommand` or domain change events: no undo entry, autosave, repeated graph compilation or accidental triggering of a replacement voice. The bounded FaustWasm/AudioWorklet event-control path delivers explicit pulse generation and release; a rapid UI button press must not be lost merely because ordinary slider values are coalesced or smoothed. Initially host messages have render-quantum boundary latency; future scheduled commands can target a specific audio frame. Do not conflate that limitation with internally generated DSP pulses, which are sample-aligned. Replacements start from defined state and must not synthesize false pulses; arbitrary state transfer remains separate work.

**Layering and UX.** Keep `EnvelopeGenerator`, parameter/port definitions and validation in Domain; registry/presets and runtime action contracts in Application; reusable edge detector, segment math, state machine and emitters in Audio; browser transport/event delivery in Infrastructure. Use `NodeFrame`, ordinary conditional parameter editors, tokenized event sockets, a capability-driven trigger action (where applicable) and the shared Phase 6.18 visualization panel for the configured envelope curve and optionally its measured output/playhead. Static preview is valid while stopped; live telemetry is generation-qualified, not persisted and never drives DSP. Provide built-in AD impact, slow swell and ADSR examples using the preset catalog, plus a complete impact example patch with wiring. Custom envelope definitions will need immutable versioned point data and atomic history once implemented; they are distinct from live playhead telemetry.

**Acceptance.** Test actual compiled Faust at 44.1/48 kHz: falling/constant/disconnected input, oscillator rising edges, exact segment timing/endpoints and bounded amplitude, onset slope, retrigger continuity, early gate release, sustain, looping with zero-duration safeguards, shared trigger alignment across nested graphs, typed route validation and persistence, tempo/division/reset/wrap behavior, manual action latency and stale generation rejection, and no recompile or graph/history mutation on events. Render the worked pitch/amplitude patch offline to verify its frequency and level trajectories and distinguish clipping from amplitude jumps. Published browser tests cover shared editors/visualizations, presets, live parameter changes and transient actions. Phases 7.1.1–4 provide continuous AD, typed event conversion/routing, rhythmic runtime sources and gate-aware AR/ADSR and Loop envelopes; preview visualization, broader presets/worked patches and custom envelope definitions remain future work.

**Implemented Phase 7.1.5 — Envelope visualization.** In the Envelope node, Show plot → View → Envelope curve displays the configured trajectory from rest, with normalized level (0–1) and proportional timed segments in milliseconds. The same view expands using the shared scope panel. AR and ADSR hold until the gate closes: the shaded hold width is illustrative, not a fixed duration. Loop includes its configured rest only when nonzero. Curve exponents use the same rising and falling power formulas as the DSP. Base edits and presets update the preview even while stopped. The measured output underneath is the existing bounded signal scope, independent of the preview; expand to change its timebase. It shows the actual routed modulation, including early releases, retriggers, modulation and mute, rather than synthesizing a waveform from the settings. Implementation: [PR #14](https://github.com/wgabel/orbit2/pull/14).

The Faust envelope state machine exposes a passive graph-qualified stage/progress bargraph (`e_<compiled-node-id>`). The stage is encoded as 0 idle, 1 attack, 2 decay, 3 hold, 4 release, 5 rest, plus half the elapsed fraction of the latched duration. The playback service maps the meter to its original graph and node through the compiler manifest and accepts telemetry only for the current applied revision and playback generation. Display polling is diagnostic, so very short stages may pass between refreshes; it does not predict or drive transitions. The marker projects actual stage progress onto the configured curve (not an assertion of actual amplitude or elapsed configured time under modulation). No meter is available for unreachable nodes or stopped playback; the static preview remains available, and the existing signal capture capacity applies to measured output. The mode preference is portable canvas presentation state (`envelope`), validated only for Envelope nodes. Neither opening, closing, expanding nor switching the view changes graph history, compilation or DSP state. Regression tests compare instrumented and uninstrumented DSP sample-for-sample and check the stage reports, preview geometry, persistence and browser interactions.
