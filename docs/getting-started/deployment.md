# Deployment and browser release diagnosis

[Project README](../README.md) · [Development checks](development.md) · [CI workflow](../../.github/workflows/build-and-deploy.yml)

The main-branch GitHub Actions workflow builds and tests the graph, Faust DSP, UI tokens, browser playback and published static assets. It deploys `publish/wwwroot` to GitHub Pages at [Orbit 2](https://wgabel.github.io/orbit2/). The Pages job is serialized and checks the current main runtime inputs before deployment; the original ordering guard was introduced in [PR #67](https://github.com/wgabel/orbit2/pull/67).

## Documentation-only CI

Implementation: [PR #132](https://github.com/wgabel/orbit2/pull/132) (merged; [full PR CI passed](https://github.com/wgabel/orbit2/actions/runs/45661056344), including classifier and actual deployment shell guard tests against a local Git remote). [Agent compliance passed](https://github.com/wgabel/orbit2/actions/runs/45661056372). The [first post-merge main build and Pages deployment passed](https://github.com/wgabel/orbit2/actions/runs/45662482468).

The build workflow always reports the existing `build` check, runs the change-classifier tests and validates documentation links. The separate agent-compliance workflow is unchanged. The shared [change-scope policy](../../scripts/ci-change-scope.mjs) excludes only Markdown under `docs/`, root AGENTS.md, the Copilot instructions, PR template and non-executable agent routing JSON. Reference-patch JSON, unknown paths, tests, workflow files and runtime code require full CI; PR titles do not determine skipping. Renames consider both paths. PRs compare merge base to head; main pushes compare before and after, including all commits in the push. Mixed PRs still build on documentation closeout commits. Manual runs, uncertain or unavailable history and forced pushes trigger full CI.

Documentation-only runs skip .NET setup, Faust, app tests, publishing, benchmarks, artifacts and deployment. A built main revision may deploy after a newer documentation-only merge: under the existing Pages lock the deploy job fetches current main and requires the built commit to be its ancestor with no changed runtime inputs. A newer runtime change or divergent history rejects the artifact; unexpected Git errors fail the guard. Release identity remains the actual built revision, which may precede documentation commits. Manual dispatch on main can force a rebuild/deploy.

Run the classifier and real Git-history fixtures with `node --test tests/tooling/CiChangeScope.test.mjs`. End-to-end verification (2026-11-25): documentation-only [PR #133](https://github.com/wgabel/orbit2/pull/133) and its [PR build](https://github.com/wgabel/orbit2/actions/runs/45662694426/job/139376482708) and [main push build](https://github.com/wgabel/orbit2/actions/runs/45663005951/job/139377566498) passed with six classifier tests, links checked in 114 Markdown files and the explicit `Documentation-only change: skip runtime build.` message. Compliance passed and deployment was skipped for both. The earlier runtime main build at `522bc5c3ec747937bd938414994d4c1e3c10795e` completed after the documentation merge advanced main to `6490b739e0d7911e507178d81434ae5a0dbbefef`; its [actual Pages deployment job](https://github.com/wgabel/orbit2/actions/runs/45662482468/job/139379927626) reported `Built runtime inputs match current main.` and successfully deployed the built revision. Stale runtime and failed-fetch rejection are covered by the local Git-remote deployment regression test. No reuse of prior mixed-PR builds is implemented.

## CI benchmark optimization

Implementation: [PR #202](https://github.com/wgabel/orbit2/pull/202), [runtime CI verified](https://github.com/wgabel/orbit2/actions/runs/46135388344) at implementation head `6c271260aff17f3a6216ba42d5744188faf308e1`; merged. All eight editor scenarios and the three new orchestration tests passed. The consolidated suite measured 301.172 seconds (excluding fixture preparation and host launch/close); individual scenarios took 11.797–70.933 seconds. Different hosted runners and changing runtime inputs preclude a controlled speedup claim.

The regular runtime build invokes the [editor suite](../../scripts/benchmark-editor-suite.mjs) using `node scripts/benchmark-live.mjs --editor-suite <fixture-directory>`. The suite runs the same eight report-producing editor scenarios sequentially on one loopback server and Chromium process. Each profile still starts a fresh browser context and imports its fixture; instrumented and ordinary measurement passes remain separate. The suite sets and restores every scenario-specific flag, including the quiet-root and folded-demand assertions, and propagates a failed scenario to CI. Existing report filenames, artifact directories, profile coverage and single-scenario CLI commands remain supported. Per-scenario and suite wall times are logged for CI analysis. The report harness fingerprint includes the suite implementation; do not compare new shared-host timing to older independent-launch reports as a controlled app performance result.

The external DSP renderer, offline DSP, functional browser checks and historical paired benchmark workflow remain unchanged. No benchmark or assertion is skipped. Current CI requires all runtime checks; any future selective execution must preserve deterministic regression coverage and explicitly update this policy. See [delivery slices](../roadmap/foundation.md#ci-benchmark-optimization-ci-bench).

### Workload deduplication acceptance for S3

The first candidate is the overlap between the ordinary 50-node idle/pan/zoom workload and the all-expanded expansion matrix. Before reusing a result, prove identical saved fixture, viewport, playback and revision, eligible/expanded IDs, instrumentation, warmup, sample duration and preceding interaction state. If they differ, retain both or explicitly redesign a matched workload with separate provenance. Do not equate render-count, folded-resource or composite telemetry passes with uninstrumented timing: those passes have distinct assertions and initialization contracts. Repeated setup may be removed only when fresh-context isolation or a verified reset preserves all necessary state and cleanup checks. Preserve raw report compatibility and list all retained regression assertions; time changes separately from application performance claims.

**S3a audit and implementation:** Standard editor-50 idle/pan/zoom is not equivalent to the expansion-matrix all-expanded pass: the matrix explicitly verifies the expansion IDs and settles before timing; the ordinary playing pass follows a stopped drag and reversible parameter edit, and its revision/history differ. Neither observation is removed or reused. Render-count, folded-resource and composite telemetry runs retain separate instrumentation and their distinct assertions.

The [bulk expansion helper](../../scripts/benchmark-expansion-state.mjs) consolidates the redundant per-frame browser state reads in expansion-matrix transitions and folded-resource bulk setup/restore. It takes two full snapshots per transition (before and after), plans only required changes in eligible order, and awaits the real toggle's requested state after every click. Invalid/missing/duplicate frames, invalid toggle state, a failed wait or an incorrect final state fail the run. The matrix retains its four cases in both playback states, final restore, 1s settling and all measurement windows. Folded resource assertions, monitor sampling, single-node transitions and scope cleanup remain unchanged. No instrumentation is mixed, no report schema or settings are changed, and the helper is included in the harness fingerprint.

For N eligible nodes, the matrix previously used N individual reads plus a final state read per transition; it now uses two bulk reads. This is a reduction in browser round trips, not a measured wall-time speedup. `EDITOR EXPANSION SETUP` and `EDITOR FOLDED SETUP` logs expose actual changed-node and snapshot counts. [PR #203](https://github.com/wgabel/orbit2/pull/203) merged after [full CI](https://github.com/wgabel/orbit2/actions/runs/46137850684) passed at implementation head `d8dd2dbe7af6746421f3a883a20220cff2e5a420`. The ten 49-eligible-node matrix transitions used 20 bulk snapshots instead of 500 individual/final reads, with the original 196 actual toggle operations and 24 timing windows. Folded-resource setup and restore each changed 48 nodes with two snapshots. Four helper tests passed and all reports were produced.

S2 measured 301.172s; observed difference 37.661s (~12.5% lower). Separate hosted runners and benchmark harness changes mean this is not causal or controlled performance evidence.

**Remaining deduplication decisions:** ordinary 50-node timing and all-expanded matrix timing differ in preceding actions, settling and explicit expansion provenance; 200 desktop and narrow viewport differ in geometry and input environment; 500 is a distinct capacity/import case. Render counters change measurement conditions and provide assertions absent from ordinary timing. Folded frame telemetry tests two folded consumers against an independent live control, while folded-resource tests all/one expanded with scope allocation and canvas-wide demand; one cannot substitute for the other. Composite navigation timing and composite resource/telemetry probes operate in different instrumentation and scope histories. Resource polling stability, repeated before/after snapshots, per-toggle settling, Stop cleanup and diagnostic warmup protect correctness or measurement meaning; do not collapse them to save a delay. Keep fresh contexts until a reset is proven equivalent, and do not cache fixture hashes across changed bytes or copy results between reports. S3a removed proven duplicate round trips; no further timed window was established as an exact duplicate. Finish S3 rather than repeatedly optimizing minor test overhead.

**S4 handoff:** the offline DSP benchmark has control binding and paired master hash checks at both sample rates; the external renderer has compiler build/reuse, live control/replacement and voice cleanup/replay assertions even when CDP timing is unavailable. Neither may be moved wholesale into an optional timing job. Functional published editor and browser graph smoke are mandatory. The editor runner currently couples actions/assertions to measurement wrappers. A fast regression mode should execute the same assertion-bearing operations and fixture/state coverage, without unnecessary timing instrumentation or diagnostic-only repetitions, preserving observation durations where needed to establish liveness/stability. Keep full diagnostic reports and standalone CLI/historical pairing available; do not relabel an abbreviated run as a full timing report. Define explicit coverage requirements and tests before switching regular runtime CI to a shorter plan. In S5, independent diagnostic jobs may be scheduled/selected by conservative change impact and run against the exact published artifact; unknown or mixed impact must fail closed to full applicable coverage. No CI execution policy changes in S3b.

### S4a shared correctness-only editor windows

The [editor window executor](../../scripts/benchmark-editor-window.mjs) owns the shared action/settle sequence and deterministic render-count assertions. The [editor runner](../../scripts/benchmark-editor.mjs) attaches its existing rAF/long-task/CDP collector only for the full benchmark. The opt-in standalone `node scripts/benchmark-live.mjs --editor-regression <fixture-directory> <regression-report.json> [profile IDs]` invokes the same actions, viewport, import, expansion/navigation, playback, counter checks, lifecycle probes and Stop cleanup as `--editor`; it does not open a CDP performance session or install frame/long-task timing observers. This first slice intentionally retains all waits and repetitions, including post-action settling and liveness intervals. It does not claim a shortened full CI path yet.

The correctness-only report uses `kind: external-editor-regression`, `settings.timingCollected: false`, and per-fixture `checks` (state/workload/expansion, render counters and parameter access when applicable) instead of timing `measurements`. It retains fixture SHA, harness SHA, revision, environment, initial/final geometry and existing lifecycle results, but omits import/play wall metrics and per-window FPS, frame gaps and CDP deltas. The paired benchmark comparator accepts only the full benchmark kind. Existing full reports and historical CLI behavior are retained.

[PR #205](https://github.com/wgabel/orbit2/pull/205) merged after [full CI](https://github.com/wgabel/orbit2/actions/runs/46139105082) passed, including three focused tests and the real editor-50 render-count shadow check (ten action windows, distinct report kind, fixture/revision/harness identity and folded-consumer lifecycle). The ordinary eight-scenario suite measured 283.164 seconds on that hosted runner; no controlled speedup claim.

### S4b full editor regression suite and parity

Run `node scripts/benchmark-live.mjs --editor-regression-suite <fixture-directory>` to execute the same eight scenarios and nine fresh browser contexts from the [suite plan](../../scripts/benchmark-editor-suite.mjs). Each report uses a distinct `regression-` filename prefix and correctness-only kind; the original benchmark reports, fixtures, settings, environment flag restoration, instrumentation boundaries and error propagation are unchanged. `EDITOR REGRESSION SUITE WALL/TOTAL` logs expose execution wall times without overwriting ordinary timing logs.

The [independent acceptance inventory and validator](../../scripts/validate-editor-regression-suite.mjs) require eight report pairs, nine profile contexts, 82 action-window identities and the named composite/folded lifecycle sequences. They check exact fixture hashes, revision, harness, environment, settings and expansion/navigation identity; both modes must independently satisfy the expected operation list, so matching incomplete results cannot pass. Regression reports cannot carry timing-window fields or masquerade as performance reports. The shared runner continues enforcing deterministic render, revision, geometry and resource assertions; the validator checks the existence and coverage of the resulting evidence, not equality of nondeterministic render counts or durations.

CI continues to run the full diagnostic suite for every runtime change. For harness-changing PRs the bounded shadow expands to the complete correctness-only suite using the exact same published build, saved fixture files and hosted runner, then invokes `node scripts/validate-editor-regression-suite.mjs <fixture-directory>` before uploading both report sets. Unit tests cover plan equivalence, missing coverage in both modes, wrong fixture/scope/provenance, unexpected timing metrics, missing counters and missing lifecycle steps. This shadow is temporary parity validation overhead, not the proposed steady-state CI policy. All existing waits are retained: the only removal is optional per-window performance collection from correctness-only mode; reducing liveness/stability delays or repeated diagnostic work requires an explicit equivalent assertion contract. S4c will address DSP and the change to regular CI.

## Published playback resource diagnostics

**Observed:** [November 27 successful run](https://github.com/wgabel/orbit2/actions/runs/46058671464) had three anonymous HTTP 404 console errors during published editor playback; [November 28 pre-consolidation run](https://github.com/wgabel/orbit2/actions/runs/46132950294) had two; [PR #202 successful run](https://github.com/wgabel/orbit2/actions/runs/46135388344) had three. Playback, nested graph edits and workspace restoration succeeded in all three. The errors predate consolidation. Their resource paths and impact remain unknown: [the playback smoke test](../../tests/browser/PublishedPlaybackSmoke.mjs) currently logs console error text without identifying the failed request. The [entry document](../../src/Orbit.UI/wwwroot/index.html) does not declare a favicon, but an automatic favicon request is only a hypothesis, not a diagnosis.

**Planned contract:** log URL, HTTP status (or network failure reason when no response exists), resource type and scenario context for unsuccessful resource loads. Separate HTTP responses from request failures; avoid classifying expected cancellation as a missing asset. Use explicit, narrowly justified optional-resource exceptions only after observing the actual requests. Unexpected missing required runtime assets (framework, JS, CSS, WASM, compiler/worker, persistence and other required assets) must fail verification. Fix confirmed asset/path errors rather than suppressing console messages. Preserve the existing rejection of unversioned assets and stale-build simulation. Verify successful published playback and a deterministic negative test for a required missing asset. See [delivery slices](../roadmap/foundation.md#published-playback-resource-diagnostics-ci-playback).

## Browser release identity and cache invalidation

Every CI publish includes the Git commit and workflow run number in its editor build identity and published manifest. Versioned CSS, editor JS, audio and persistence module paths prevent stale runtime asset trees from being mixed across deployments. Startup checks an uncached manifest and requests the correct page for a mismatched deployed commit. Local builds identify themselves as `dev`; already-open tabs can remain on an older version until reloaded. See [PR #72](https://github.com/wgabel/orbit2/pull/72) and the [original implementation record](../archive/legacy-readme.md#browser-release-identity-and-cache-invalidation).

If a merged change appears absent, first check the latest **completed** Pages deployment, its commit and the build identity shown by the running editor. Verify the live fingerprinted JS/CSS before diagnosing browser cache. Do **not** clear site data indiscriminately: IndexedDB may contain saved patches.

For precise historical implementation detail, including error conditions and verification coverage, see [the archived deployment section](../archive/legacy-readme.md#browser-release-identity-and-cache-invalidation). For runtime limitations use the [current source and tests](../quality/testing.md).
