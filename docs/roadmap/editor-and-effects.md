#### Phase 6.18 — Signal analysis and visualization (partial: 6.18.1–6.18.5 implemented)

- Partial (6.18): shared observation, visualization, integrated node plots and processor response curves implemented; dynamic tap allocation (6.18.8) is implemented ([PR #20](https://github.com/wgabel/orbit2/pull/20)); passive analyzer sinks and advanced analysis remain planned.

- **6.18.1 — Observation infrastructure (implemented):** bounded Faust output taps, explicit master-channel isolation, graph-qualified manifest, generation-aware capture leases and analysis contracts. Offline/worklet regression coverage for master equivalence, nested routing, mute/bypass, leakage and bounded resources. Device-scale profiling and long-history capture remain later analysis work.
- **6.18.2 — Oscilloscope and level meter (implemented):** reusable selected-node scope, browser-side time-domain display, peak/RMS, timebase, zero-crossing trigger and bounded slow-modulation history. Known sine, clipped and low-rate modulation regression coverage.
- **Parameter editing UX refinement (implemented):** independent display-scale metadata, segmented logarithmic oscillator frequency rail and consistent modulation visualization; unchanged physical values and DSP semantics.
- **6.18.3 — Spectrum analyzer (implemented):** reusable FFT display with logarithmic frequency and calibrated peak dBFS axes, selectable window/resolution and time-based power smoothing; known fundamental/harmonic/noise tests and shared capture with the oscilloscope. Follow-up in review: window-weighted DC removal prevents artificial first-bin sub-bass while keeping real low frequencies and dBFS calibration; [PR #66](https://github.com/wgabel/orbit2/pull/66).
- **6.18.4 — Integrated and expanded views (implemented):** capability-driven shared `NodeVisualizationPanel`, compact collapsible waveform/spectrum/level plots, expand/mode/source controls, visible-only rendering, tokenized design and compatible per-graph layout persistence; no graph history or DSP restarts for display changes.
- **Cycle timing and pulse width refinement (implemented):** shared nominal cycle/polarity durations, seconds-based editing of free oscillator rate, approximate live period, conditional modulatable square duty with schema-1 compatibility, and oscillator-output one-configured-cycle scope with bounded history.
- **6.18.5 — Processor response curves (implemented):** pure tested response providers matching the actual parametric EQ and four filter modes, configured and instantaneous effective parameter response, sample-rate-aware logarithmic axis, stopped previews, audition notices and shared compact/expanded layout persistence; numerical and measured offline Faust parity. Implementation: [PR #4](https://github.com/wgabel/orbit2/pull/4).
- **6.18.8 — Dynamic signal tap allocation (implemented):** bounded, demand-driven runtime allocation to visible live plots replaces compile-time priority allocation. Releases unused bindings, shares identical signals, distinguishes routing failure from true capacity exhaustion and preserves master isolation and continuous playback. See [Signal observation and analysis](../audio/signal-observation.md#signal-observation-and-analysis-phase-618--partial). Ship before 6.18.6/6.18.7 or other new features; multi-drone device profiling remains follow-up. Design: [PR #15](https://github.com/wgabel/orbit2/pull/15). Implementation: [PR #20](https://github.com/wgabel/orbit2/pull/20).
- **6.18.6 — Dedicated analyzer sink (planned):** validated passive mono observation node for any compatible signal, reusable visualization panels, independent placement/resizing, analyzer-only reachability, nested graph persistence and undo/redo; prove audible master isolation.
- **6.18.7 — Advanced analysis (planned):** synchronized input/output spectral comparisons, bounded spectrogram history and profiling of multi-drone workloads; reuse chart infrastructure for future envelopes, automation and sample-based nodes.

Deliverable: inspect an oscillator waveform, harmonics, modulation and levels directly on the node; expand the same visualization without changing playback; see an EQ/filter's configured response when stopped and effective response during playback; attach an independent analyzer anywhere in a patch without changing its audible path.

#### Phase 6.21 — Canvas-first workspace and node library (partial: 6.21.1–6.21.3 implemented)

**Goal:** maximize usable canvas area on phones and tablets without losing the desktop editor's functionality. The motivating Android portrait screenshot showed the canvas container occupying about 48% of the available app height, with further overlap from status and annotation controls. Target approximately 85–90% of the usable app viewport in the normal mobile workspace, measured excluding browser/system chrome and when panels are closed; aim for more in fullscreen. Treat this as a measurable design target rather than a guarantee for every viewport. The same responsive workspace, canvas state and node renderer must serve the root and every nested graph.

- **6.21.1 — Responsive canvas-first shell (implemented):** use a full-available-height layout (dynamic viewport height and safe-area insets, with an appropriate fallback), a compact single-row top bar and a single-row bottom tool bar; do not allow toolbars to wrap into multiple permanent rows. The top bar retains the app/active patch and compact breadcrumb or back navigation, current BPM, Play and Stop. The bottom bar exposes Nodes (+), Outline, Edit, View and More. Put zoom in/out, current percentage, reset to 100% (for example tap percentage or View), and Fit in a small floating edge control; keep it movable or easily out of the way where needed. Keep local and recursive patch counts accessible through a compact non-overlapping status readout or View details; remove persistent desktop-only gesture instructions from the mobile canvas. Provide usable touch targets, accessible labels and focus, and landscape layouts that preserve canvas space. Keep the desktop workflow familiar and reuse shared components rather than mounting separate live canvases or playback controllers.

- **6.21.2 — On-demand tools and contextual panels (implemented):** move the permanent toolbar controls into dismissible, scrollable bottom sheets on mobile (appropriate anchored panels on desktop). Nodes opens the library; Outline reuses the existing searchable hierarchy with locate/open and nested navigation; Edit exposes graph undo/redo, separate annotation undo/redo, selection mode, grouping and other editing operations; View exposes cable labels (All/Modified/Selected/Off), annotation visibility, zoom/Fit/reset, counts and gesture help; More exposes patch/library management, diagnostics/performance, and advanced transport settings. Tapping BPM opens tempo editing, reset transport, playhead/beat status and synchronized rates. Show relevant actions such as delete, describe, create visual group, group/ungroup and scope for the current selection rather than reserving canvas space for inactive buttons. Reuse existing commands, disabled-state rules, protected drafts, keyboard shortcuts and root playback state. Retain access to node presets, racks and performance keyboard. Ensure only the intended panel is active; close/reclaim space when its action completes or the user dismisses it. Support Escape/Back and accessible focus restoration; never hide errors or make a dirty draft disappear silently.

- **6.21.3 — Searchable visual Node Library (implemented):** replace the add-node dropdown on both desktop and mobile with a shared searchable, categorized list. Each row has a distinct recognizable node-type icon, category accent, canonical name, short purpose description and Add action. Provide All and category filters, search by name/alias/description, recently used nodes and user favorites at the top (persist locally; reconcile unavailable types). Group results by category and preserve a meaningful order; distinguish empty searches and unavailable context-specific factories. Selecting an eligible node invokes the existing validated add operation, places it in the currently visible canvas without unexpectedly changing the viewport, closes the library after success and leaves errors actionable. Respect root-only master output, nested rack rules, supported composite factories and stable type keys; integrate future reusable custom modules (7.4.3) with the same catalog rather than requiring that milestone first. The node list and icon registry are presentation-owned, not graph or DSP metadata.

  Proposed category accent palette (dark-theme design references; map through shared semantic design tokens with accessible light-theme counterparts, not hardcoded component colors):

  | Node category | Accent | Example icon/entry |
  |---|---|---|
  | Audio generators | Blue `#42aaca` | Waveform / Oscillator, radio/noise |
  | Modulation and automation | Mint `#65cdb1` | Activity / LFO, curve / Envelope |
  | Audio effects | Purple `#ac82dc` | Waves / Reverb, EQ sliders |
  | Sequencing and musical events | Amber `#e5b563` | Notes / Note sequencer, step grid |
  | Signal processing and mixing | Orange `#e28b67` | Mixer sliders, gain |
  | Composite patches | Pink `#d27ba8` | Nested boxes / Drone or composite |
  | Input and output | Slate/grey `#9ba9ba` | Input/output arrows / racks, master |

  Centralize type icon, category, display name, summary and semantic accent resolution in a presentation registry (reuse existing node definitions and role classification where applicable); ensure every registered node has deliberate metadata or an explicit accessible fallback and new nodes require no renderer changes. Apply the same recognizable icon/accent to the library, compact and expanded node headers, searchable outline, preset lists and composite breadcrumbs. This proposed category expansion refines the current smaller [design-system role palette](../editor/design-system.md); update its contract and tokens in the implementation, preserve role-aware distinctions (such as an oscillator used as modulation), and keep audio/modulation/trigger/gate/clock cable and port semantics independent of category colors. Use text, symbols and contrast as well as color. No new DSP types are implied by the visual grouping.

- **6.21.4 — Touch-first canvas gestures (planned):** drag blank canvas to pan, pinch around the two-finger midpoint to zoom within existing bounds, drag a node header to move, tap to select, long-press to show contextual actions, tap output then input to connect, and double-tap a composite header to open it (retain explicit Open action as well). Add an explicit selection mode for touch marquee/multi-select instead of requiring Shift+drag, reusing Phase 7.4.1 selection semantics. Retain desktop mouse, keyboard, wheel and drag-to-connect behavior. Distinguish taps from drags, pinch and long press; prevent accidental node edits or movement when entering/exiting multi-touch, honor cancellation/pointer capture, keep sliders and scrollable panels interactive and avoid page scrolling during canvas manipulation. Use existing CanvasViewport/world-transform and graph-qualified commands, not an independent mobile coordinate system.

- **6.21.5 — Compact, auto-expanding and pinned nodes (planned):** introduce workspace modes **Auto-expand** (default on mobile; optionally on desktop), **Compact** (manual expansion only) and **Detailed** (existing all-expanded view; desktop default initially). Auto-expand starts nodes compact, showing their icon, category accent, name, essential type-specific summary, available ports and important state indicators (mute/bypass/selection/pin as applicable); for example, oscillator waveform + frequency/gain, filter mode + cutoff, sequencer active step + pattern length, composite name/ports + Open action. Keep the existing shared parameter content, plots, presets, rack editors and commands available in the expanded frame. A tap/click expands a compact node; tapping another node collapses the previous unpinned node and opens the new one, and tapping the empty canvas collapses all unpinned nodes. A visible pin toggle on expanded nodes keeps them open across outside clicks and subsequent selections; multiple nodes can be pinned, unpin restores auto-collapse, and a manual collapse can clear its pin explicitly. Dragging a node, manipulating a parameter/port, scrolling its contents or interacting with a related editor must not inadvertently toggle expansion. Respect protected drafts and keep the expanded node accessible above overlapping neighbors. The explicit Compact mode supports manual expansion/collapse without automatic outside-click behavior; Detailed mode continues showing all controls and does not discard saved pin choices.

  Roll the parameter body down/up in place with a short eased animation (initial motion tokens: about 180 ms ease-out expansion, 140 ms ease-in-out collapse), keeping the header anchored and other node world positions unchanged. Honor reduced-motion preferences. Keep all routable ports accessible or represented by unambiguous compact anchors; measure actual port geometry during changes, update cable endpoints and hit testing smoothly, and avoid disappearing connections, expensive per-frame graph edits or forcing a global reflow/fit. Fit/placement must use current measured bounds; avoid adding new nodes under open panels. Collapse hidden visualization/telemetry subscriptions where possible; preserve plot settings, release unused live taps according to Phase 6.18.8, and avoid restarting audio or recompiling DSP on expansion, pinning or collapse. Maintain a single shared NodeFrame with per-type compact summary metadata and existing expanded content, not alternate mobile node implementations. Persist display preference and graph/node-qualified pins in compatible presentation-only workspace/patch layout data; reconcile missing/deleted/restored nodes, nested navigation and import/reload without changing DSP configuration or undo history. Transient automatic focus/expansion is separate from authored layout and pins. Keep node heights/summary widths stable under live telemetry.

- **6.21.6 — Fullscreen, responsiveness and regression verification (planned):** add optional focus/fullscreen canvas mode with a discoverable exit and essential playback access, browser fullscreen where supported and graceful fallback. Validate portrait and landscape, tablet, narrow phones (for example 360 × 640 and 390 × 844 CSS pixels), desktop and root/nested navigation. Measure canvas rectangle vs usable application viewport before/after, verify no panel overlap or toolbar wrapping when closed, correct touch hit targets and selection, focus and reduced-motion behavior, stable world positions/port anchors across expand/collapse and zoom, multiple pins and compatible save/restore. Exercise node search/filter/favorites/recent, context-specific add/placement, all retained commands, plot tap release/reacquisition, continuous playback while changing display and graph history isolation. Use 7.3.3 editor responsiveness metrics and representative large/nested patches (e.g. the motivating ~67-node/42-connection patch) to compare FPS/frame gaps while panning, zooming or expanding nodes, and monitor underruns. Do not claim mobile usability or performance without measured browser/device evidence; add state, geometry and browser regression coverage, and update the actual [patch editor usage guide](../usage/patch-editor.md) as each stage ships.
