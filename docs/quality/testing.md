## 14. Testing and acceptance criteria

The core model should be independently unit testable without a browser or Faust. Offline DSP tests and browser integration tests cover the actual audio path.

| Area | Essential acceptance test |
|---|---|
| Node model | Create sine/processor nodes with stable port and parameter identities. |
| Connection validation | Reject invalid endpoints, incompatible ports, duplicate edges and forbidden cycles. |
| Modulation | Base 440 Hz with +/-100 Hz source yields 340–540 Hz without changing BaseValue. |
| Multiple sources | One LFO routes to several parameters; a parameter combines multiple valid sources. |
| Phase | Frequency changes advance existing phase instead of accidentally resetting it. |
| Sample rate | Oscillator frequency and tempo sync correct at both 44.1 and 48 kHz. |
| Transport | 120 BPM quarter note = 0.5 seconds; synchronized LFOs share expected phase/reset. |
| Envelope and rhythmic events (partial: AD and typed adapters implemented) | Oscillator edges trigger one AD each, exact duration/endpoints at 44.1/48 kHz, retrigger from current value, gate-off release, shared trigger fan-out, typed routing and nested persistence, no phantom pulses across transport wraps/replacements and no graph revisions on runtime actions. |
| Pitch and instruments (partial: shared pitch tracking implemented) | Reference-note conversion and exact octave/harmonic ratios, compatible additive Hz and pitch modes, sample-aligned pitch/gate/trigger/velocity, no graph commits on note actions, independent voices, valid editable templates and bounded CPU/headroom. |
| Keyboard performance / continuous sequencing (7.2.8 — partial) | Keyboard isolation, latched pitch, generation-safe live actions and no per-note compilation in 7.2.8a; multi-bar/free loop boundaries, Holds, glide and atomic pattern edits in 7.2.8b; quantized live recording, atomic commit/undo/persistence and future-boundary updates in 7.2.8c ([PR #19](https://github.com/wgabel/orbit2/pull/19)); Note-mode articulation implemented ([PR #87](https://github.com/wgabel/orbit2/pull/87)); per-note gate length merged ([PR #111](https://github.com/wgabel/orbit2/pull/111)): distinct gate releases, tie inheritance, onset-latched edits, migration, undo and selected-step editing; velocity data merged ([PR #113](https://github.com/wgabel/orbit2/pull/113)): explicit zero vs inherit, invalid/partial payload rejection, migration, hidden-slot round-trip and undo/redo; velocity scheduling merged ([PR #114](https://github.com/wgabel/orbit2/pull/114)): onset-latched values, repeated pitches, tie/rest, explicit zero/default, tempo/seek/reset/wrap and compiled four-output regression at 44.1/48 kHz; velocity editor CI verified, awaiting merge ([PR #115](https://github.com/wgabel/orbit2/pull/115)): independent slots, zero/default, undo/redo, narrow viewport and Rest/Pitch-only visibility; timing data and scheduling merged ([PR #117](https://github.com/wgabel/orbit2/pull/117), [PR #118](https://github.com/wgabel/orbit2/pull/118)); timing editor (merged, [PR #119](https://github.com/wgabel/orbit2/pull/119)): independent signed values, millisecond readout, duration changes, undo/redo, narrow viewport and Rest/Tie/Pitch-only visibility; humanization command (merged, [PR #120](https://github.com/wgabel/orbit2/pull/120)): seeded determinism, bounded direction/strength, selected active onsets only, silent and hidden slots preserved, zero-strength no-op, atomic undo/redo and patch round-trip; humanization editor (in review, [PR #121](https://github.com/wgabel/orbit2/pull/121)): explicit range, seed and timing direction, no-op disabled, independent slot values, one undo/redo and narrow viewport. |
| Audio pitch shifting (Phase 6.20, planned) | Single-tone and mixed-chord spectral peaks follow the same transposition ratio at 44.1/48 kHz, sustained duration/tempo preserved, latency and alias/sideband quality measured, silent and bounded output under extreme modulation, transparent dry/zero shift, click-safe audition, independent instances and bounded CPU/memory. |
| Resonators and modal synthesis (planned) | Compiled impulse responses at 44.1/48 kHz match tuned center and amplitude T60, silence does not self-oscillate, repeated excitation retains ringing state, rapid modulation stays finite/stable, modal frequency and independent decays match configuration, and template/bank state round-trips with undo and persistence. |
| Fan-out | One output can feed several processors without duplicating generator runtime state. |
| Composite | Flattening a subgraph produces equivalent routing to a flat graph. |
| Rack ports | Add/remove/rename/reorder updates both views; rename/reorder retains connections. |
| Rack deletion | Parent and child connections removed atomically; no dangling references. |
| Events | Successful command publishes committed change set; rejected command publishes no change event. |
| Subscribers | Disposing subscription stops delivery; independent listeners can coexist. |
| UI separation | Node movement/opening subcanvas does not recompile or restart audio. |
| Compile revisions | Stale results cannot replace a newer successful runtime. |
| DSP failure | Last valid runtime remains active; error is displayed to the user. |
| Presets | Two instances have independent parameters and DSP state. |
| Node audition (implemented) | Mute last node in one mixer lane while preserving other lanes; mute fan-out including composite and modulation outputs; bypass eligible effects with unchanged dry signal; retain DSP state, parameters and wiring, verify smooth transitions without recompilation, mute precedence, undo/redo and compatible persistence. |
| Individual node presets (implemented) | Validate every shipped configuration; reject invalid batch without mutation; application preserves identities and wiring, emits one revision and undo entry; base-only updates avoid recompilation; custom groups survive reload and library edits do not alter existing nodes. |
| Signal analysis (implemented core; advanced analysis planned) | Compare master samples with taps on/off; no observation-channel leakage, phase reset or graph compile on view changes; verify root/nested port mapping, weighted input and post-mute/bypass output, known waveform/FFT/peak/RMS, slow LFO history, stale-frame rejection, hidden-view cleanup and bounded resources. |
| Dynamic signal taps (6.18.8 — implemented) | [PR #20](https://github.com/wgabel/orbit2/pull/20) adds compiler, runtime and offline WASM regressions for more than eight reachable outputs, eight concurrent auxiliary slots, ninth-request capacity feedback, reuse, alias sharing, distinct unrouted status, nested/stale-generation cleanup and sample-identical master audio without graph recompilation; browser/device profiling remains follow-up. |
| Processor response (Phase 6.18.5 — implemented) | EQ center gain, Q bandwidth, filter modes and Nyquist limits match offline Faust measurements at 44.1/48 kHz; distinguish base/effective estimates, live spectra and stopped previews. |
| Analyzer sink (planned) | Analyzer-only branches are observable but silent at the master; explicit graph edits round-trip with undo and persistence; visualization preferences restore without changing graph topology or audio. |
| [Patch documentation](../editor/patch-annotations.md) (notes, descriptions, groups and overview implemented; visibility implemented; outline implemented) | Notes, aliases, labels, groups and overview round-trip with root/nested layouts and named snapshots; old documents restore empty annotations, invalid data is rejected atomically, annotation history and text editing remain independent of graph history, visibility/zoom/outline retain authored state and navigate valid IDs, and graph revision, compilation and playback generation stay unchanged. Regression coverage includes immutable snapshots, shared bounded history, placement, malformed data, nested restoration, deleted target reconciliation, canonical names, explicit group membership, atomic movement/undo, frame-only resizing/deletion, metadata-only named save search, annotated example validation, zoom hysteresis, per-canvas visibility, hidden-item reveal/fit, protected drafts, and unchanged numeric badges and playback revision. |
| Patch outline (6.19.8 — implemented) | [PR #39](https://github.com/wgabel/orbit2/pull/39): filter and search aliases, note bodies and unvisited nested graphs; preserve unique graph-qualified identity, group membership, hidden visibility, history and viewport; restore saved/deleted layouts and jump across branches; published editor verifies opening during playback, locating internal nodes and revealing hidden annotations. |
| Multi-node selection (7.4.1 — implemented) | Bulk selection deduplicates and commits once to presentation, excludes master/racks, rejects foreign IDs, preserves graph revision, layout and history; measured intersection at different zoom/pan, reverse rectangle, nested graph isolation, keyboard toggle and cancellation; published editor exercises selection controls and unchanged viewport/history. |
| Composite grouping (7.4.2a — implemented) | Signed/zero amounts, typed adapters and dormant wires at the original receiver, nested ownership and protected/cyclic/stale selection rejection, one revision and history step, relative layout and descriptions, save/load, deterministic compiled samples at both supported rates, and published editor group/open/undo/redo. |
| Composite ungrouping (7.4.2b — in review) | Current edited boundary coefficient products, event adapter passthrough/fan-out, dormant wires, single-level ownership, rejection of sum/one-sided/muted/stale and metadata-loss cases, one revision/history entry, edited child layout and descriptions, descendant navigation, save/load, deterministic compiled comparisons at 44.1/48 kHz and published-editor expand/undo/redo. |
| Connection visualization (Phase 6.19.5 — implemented core) | Badge units and signs match committed receiving-port semantics; zero/dormant states remain distinct; labels follow cable midpoints behind nodes and obey visibility preferences; the editor clamps to usable canvas geometry; display changes leave graph and playback unchanged, while explicit Apply commits one amount change and undo/redo restores its badge. |
| Output safety | Controlled master gain, no unexpected discontinuity when changing base values. |
| Performance and diagnostics (7.3 — planned) | Feature-detected metrics with explicit scope/availability, no monitoring-induced graph/audio changes, session/generation correctness, bounded resources and reproducible throughput/real-time comparisons; see [performance.md](performance.md). |
| Persistence | Save/load nested graph and layout with stable IDs and equivalent connectivity. |
| Audio assets (planned) | Import and reload binary recordings, share immutable data across nodes, preserve IDs through undo/redo, handle quota and missing assets without corrupting patches. |
| Sample playback (planned) | Verify pitch/rate at 44.1/48 kHz, independent playheads, interpolation, loop bounds/crossfades, reverse and one-shot termination; reject stale asset loads during live replacement. |
| Portable packages (planned) | Round-trip a patch and its assets in a fresh browser; reject malformed, oversized or conflicting archives without partial workspace replacement. |

Use OfflineAudioContext or an appropriate offline DSP renderer for deterministic audio tests where possible. Measure spectral/frequency behavior, sample continuity and expected modulation envelopes. Browser playback and workload tests are needed to catch real-time underruns and device-specific behavior.

## CI test suite optimization

[Work slices](../roadmap/foundation.md#ci-test-suite-optimization-ci-test) · [CI benchmark contract](../getting-started/deployment.md#ci-benchmark-optimization)

The goal is to reduce repeated expensive operations, not merge independently useful assertions merely to lower the number of reported tests. Baseline: [PR #210 successful CI run](https://github.com/wgabel/orbit2/actions/runs/46149377276), sequential build job 140992417770. The harness-changing PR ran both benchmark modes; this is not typical ordinary PR duration.

| Workload | Observed time | Evidence / implication |
| --- | ---: | --- |
| C# Domain and Presentation | ~3 s test execution | 299 + 180 tests; build/restore adds time, not a reason to remove tests |
| Python | 1.055 s | 31 tests; native export/import invocations are separate setup |
| JavaScript audio units | 0.470 s | Keep fast independent tests |
| Generated graph + compiler step | 54.669 s | Node compiler test runner 50.976 s; expensive instrument matrices |
| Offline DSP step, both modes | 19.786 s | 9 profiles × 2 rates × 5 repeats = 90 renders per mode |
| Browser graph playback | 27.318 s | Includes browser driver setup; real browser worker/worklet assertions |
| Published playback | 135.449 s | Monolithic end-to-end scenarios, not only smoke |

| Full editor suite | 406.091 s | 8 reports, 9 contexts, 82 interaction windows |
| Editor regression suite | 384.720 s | Same coverage; one sequential comparison, not controlled repeated timing |

Do not add these times to estimate normal PR duration: mode selection, preparation and parallelization differ. The existing editor workload equivalence audit found no exact duplicates across the current eight reports; a smaller correctness matrix requires a new explicit assertion contract, not simply deletion. The complete diagnostic matrix and checkpoint verification remain available. Production graph/serialization/DSP/UI changes retain conservative coverage.

CI logs emit `PUBLISHED SCENARIO WALL {"scenario": "...", "status": "passed|failed", "wallMs": ...}` and `PUBLISHED SCENARIO TOTAL`. The current section is failed on an ordinary exception; preceding successful sections are retained. Forced job termination may prevent the final log. Timer excludes pre-launch server initialization and final browser cleanup; it is diagnostic wall time, not product performance. The timer's unit tests are executed by the existing benchmark test glob. Future extraction must map every assertion and state dependency, including build/asset coverage, to an explicit module and preserve the full suite until proven equivalent.

### Audio workload reduction constraints

`PhysicalSustainedInstruments.test.mjs` runs 37 semitones × 3 expressions × 3 characters per instrument/rate, or 1,332 trials for clarinet and flute at both rates. Four named chromatic tests took roughly 7–9.5 seconds each on the observed runner; these execute concurrently with other test files, so sums are not critical-path savings. Preserve the exhaustive matrix for relevant changes and full checkpoints; any representative matrix needs documented boundary and known-failure coverage, both rates and negative tests. The marimba test also has expensive repeated render cases. Factory reuse may avoid compiling the same source twice in `PhysicalInstruments.test.mjs`; compare exact bytes/options and factory identity, retain fresh mutable processor state. The offline DSP runner already caches factories by source hash. Do not share mutable processors across independent tests or skip cold/replacement/lifecycle assertions. Do not change production behavior to make tests cheaper. No reduced coverage or measured savings are claimed by S1.

### CI policy self-audit and priority corrections (S1a/S1b)

Audit revision: main `93dad718718a111a6da0dbdf103839ce9cd1f456`, with S5c.1 merged. [PR #211 CI run](https://github.com/wgabel/orbit2/actions/runs/46151404249) succeeded. The prepare log spans about 240s, playback 182s, editor 635s and aggregate build 5s. Editor and playback start concurrently at approximately 13:52:11 UTC; editor is the critical path. Full editor suite 320.056s and regression suite 299.483s, together 619.539s; both parity validators passed (18 offline rows/2 live profiles, 8 editor reports/9 contexts/82 windows). The transfer archive was 52,265,106 bytes; download steps took approximately 3–5s and both checksum validations passed. Do not optimize the small artifact overhead or cheap aggregate gate first. This run is a harness-changing both-mode PR, not a representative ordinary run or a controlled before/after comparison. PR #212 was opened before #211 merged and its initial CI still uses the sequential workflow.

**Findings to correct, in priority order:**

1. `benchmarkHarnessPath` treats every file under `tests/benchmarks/`, the build workflow, classification and aggregate verification helpers as requiring both modes, even standalone unit-test or published-smoke instrumentation edits. PR #212 is a concrete false positive: its new timer unit test is in that directory for test discovery, but is unrelated to editor benchmark workloads. S4 parity was needed to establish mode equivalence; it is not automatically needed again for an unrelated test. Revalidate affected modes only, except changes to the common regression/diagnostic workload, parity contract or unknown/shared harness dependencies that genuinely need both. Do not move tests to a different directory solely to evade the classifier; fix the classification and discovery contract.
2. The single global `benchmarkMode` couples DSP and editor work: a DSP-specific harness change requests editor parity and the converse. `performanceSensitivePath` also forces full timing for every Audio source change and selected editor/UI hot paths, even ordinary correctness work. Separate independent DSP/editor applicability and diagnostic/parity modes. Correctness remains mandatory for affected shared runtime code; expensive measurement is for explicit performance work, actual performance-sensitive acceptance, and diagnostic workflows. Full correctness checkpoints need complete applicable regression coverage, not automatically both redundant modes. Preserve controlled before/after performance evidence when required by the existing quality policy.
3. `needsRuntimeBuild` treats every non-documentation input as a runtime build; the four isolated editor exemptions still run native suites, Agent Kit export/import, Faust/compiler, offline/live DSP, graph/browser smoke and publish. Decouple published application inputs, test-infrastructure changes, verification job applicability and deploy freshness. Isolated classifier/gate tests need focused unit tests and representative actual workflow execution, not a whole app benchmark for every edit; workflow transfer or required-gate changes still need real affected job/negative-path verification. Test-only browser changes need the affected browser suite against an exact valid published build, not unrelated instrument/editor benchmark work. Keep shared build metadata, fixture generation and unknown inputs conservative. For audited independent mixed scopes, take the union of their required checks rather than defaulting to every suite solely because two safe families coexist. Never accept a missing or invalid applicability decision as permission to skip.
4. S4 correctness mode retained all 82 interaction windows and almost all waits. On PR #211, the regression suite was only about 20.6s shorter than the full suite in one sequential observation. Removing instrumentation alone is not substantial workload reduction. S4 of CI-TEST should inventory unique assertions, move pure timing combinations to diagnostics and combine independently equivalent correctness checks; use negative controls to prove retained failure detection. Full diagnostics remain available, including both rates/large/mobile/resource lifecycle cases as applicable. Do not remove distinct behavior coverage simply because actions look similar.
5. The workflow listens to every PR label/unlabel event; only the full-verification and performance-diagnostics labels currently affect mode selection. It also executes full diagnostics on every non-documentation main push, including test-only merges. Docs-only closeouts on an existing runtime PR still use the full cumulative PR diff and retrigger the same runtime checks. Audit redundant runs and add PR-only cancellation of stale runs, targeted label behavior and input-aware evidence reuse if provable. Preserve required check reporting for every candidate, exact SHA/input identity, verified merge candidate and freshness protections; do not reuse stale success or skip a new merge revision based solely on a PR passing. Separate deployment-relevant inputs from tests only after auditing all consumers; no automatic test-only deployment or skipped required deployment without proof. Main/manual full correctness policy and explicit checkpoints stay until replaced by verified equivalent policy.
6. Preparation still takes approximately four minutes before either browser runner starts. PR #211 includes about 33s for Agent Kit exporter/test/import, 50s for generated graph/compiler, 20s for offline verification, 26s for graph browser smoke and 50s for publish. Twelve separate exporter `dotnet run` invocations (including the negative import), plus probe generation and repeated build/restore, are candidates for build-once/no-build or batched invocation; preserve all positive/negative fixture checks and generated asset ordering. Measure actual command timings and test isolation first. Separate independent prep work only when critical-path savings exceed extra setup/transfer and runner cost.
7. Do not conflate test count with wall time: 479 native unit tests took about 3s total in PR #210; retain those tests. Instrument cross-products and repeated render/factory setup are better targets. Do not sacrifice both sample rates or state/voice/persistence isolation merely to reduce count.

**Target policy (planned, not active):** classify the complete diff into explicit required jobs/suites, independent mode per benchmark family and independently proven publish/deployment input impact. A suite's changed test files require that suite's verification, not every unrelated runtime suite. Full application checkpoints run complete applicable correctness coverage; request timing diagnostics independently where needed. A shared correctness/parity change requires affected full/regression shadow verification. Test selection logic and workflow changes themselves must be tested by unit/negative fixtures and real relevant positive/negative workflow runs. Unknown/shared inputs fail closed to required coverage. Preserve the existing `build` aggregate status, require successful applicable jobs, verify intentional skips, and never permit free-form skip labels. S1a is the priority before modular extraction; S1b audits trigger/setup redundancy. Acceptance must include real ordinary infrastructure-only, published-test-only, mixed runtime and full-checkpoint CI runs, actual omitted/executed job evidence, elapsed and runner time, not just classifier unit tests.
