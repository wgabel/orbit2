## 1. Purpose and goals

Orbit 2 is a browser-based modular synthesizer using C#, Blazor WebAssembly, a reusable graph compiler, Faust/WASM and Web Audio AudioWorklets. The primary performance requirement is **uninterrupted audio at the actual sample rate**, including complex drone patches, continuous LFO modulation, live edits, scope/spectrum display, and eventually keyboard performance, sequencing and multiple instrument voices.

Performance has several independent dimensions:

- **Real-time audio reliability:** can the rendering thread produce the next block of samples in time, every time? Are there underruns, interruptions or errors?
- **Audio latency:** how long between an input action and hearing its result? This matters for keyboard playing, although a sustained drone may tolerate more delay.
- **DSP processing demand:** how close is the audio engine to exhausting its rendering budget? Are we approaching a limit before an audible problem occurs?
- **Editor responsiveness:** is dragging nodes, changing sliders, interacting with wires or opening nested canvases smooth?
- **Compilation/replacement latency:** how quickly can Orbit generate Faust source, compile it, initialize a new worklet and accept a new graph without interrupting existing audio?
- **Resources:** how many reachable DSP nodes, parameter controls, observation taps, capture leases, FFTs and runtime voices are active? Do memory or resources grow over time?
- **Musical timing:** do multiple sequencers and event sources share exact boundaries, do long loops drift, and how late do manual performance events reach the engine?
- **Signal quality:** is the generated audio clipping or discontinuous? Signal clipping is not CPU overload.

**Desired performance and planned UX:** the [health target contract](performance-metrics.md#31-suggested-health-thresholds) defines proposed audio, editor and compile thresholds; the [explainable badge design](performance-metrics.md#421-explainable-health-indicators-planned-737) requires a short visible “why” next to every assessed metric. Phase 7.3.7 adds this interpretation to existing valid measurements without waiting for validated in-app DSP timing. Phase 7.3.8 [device capacity benchmarks](dsp-profiling.md#94-device-specific-capacity-and-reference-compositions-planned) establish representative mobile and desktop workloads and calibrate targets. These are planned goals, not verified current capacities.

A single number called "performance" cannot answer these questions. The monitor should expose a small number of useful, honest metrics and allow an expanded diagnostic view when something goes wrong. It should let a musician build richer patches with confidence and let a developer or AI coding agent identify the relevant subsystem before changing code.

**Delivery priority:** Phase 7.5 ([stereo audio, panning and oscillator unison](../audio/stereo-panning-and-unison.md)) should follow the 7.3.1 passive monitor, 7.3.2 compilation/runtime/resource diagnostics and 7.3.4 reproducible mono benchmark baseline. Unison multiplies waveform instances; stereo expands channel processing; graph crossfades temporarily run both old/new DSP. Establish measurements before introducing these costs and repeat the benchmark after each Phase 7.5 increment. Use the documented external/offline workflow when in-app load is unsupported. Editor monitoring (7.3.3) is recommended; the timing and advanced reports milestones need not delay Phase 7.5.

### Non-goals and invariants

- Do not redesign the graph model, audio engine or Faust execution solely to display statistics.
- Do not create a second audio context or route new channels into the master merely for monitoring.
- Do not introduce server telemetry or require a network service. Statistics are local and reports are explicitly exported.
- Do not promise to measure total computer CPU, GPU, battery use or actual speaker latency from ordinary browser APIs.
- Do not silently change output latency, sample rate, patch settings, graph content, analyzer quality or sound to improve the meter. Suggest actions and let the user choose.
- A monitor read, toggle, reset or report export must not change command history, committed graph revision, persisted patch content, musical transport, DSP source, compiled identity or playback generation.
- Do not use a displayed peak, a worklet error count, a JavaScript timer delay or a made-up CPU estimate as a substitute for actual rendering capacity or underrun statistics.
- Separate **ordinary passive monitoring** (low overhead; opt-in by opening the Performance panel) from **explicit diagnostic profiling and stress testing** (potentially expensive; separately opt-in). While closed, no recurring monitor sampling or operation timing runs. See the [on-demand collection contract](performance-implementation.md#on-demand-collection).

## Large-patch editor responsiveness (7.3.9)

**Problem:** a 191-node musical patch was reported too laggy to run. Treat editor responsiveness as an independent workload, not proof of high DSP cost. The initial code-inspection suspects include full canvas node iteration, shared effective-value dictionaries passed to every NodeFrame, whole-graph port anchor discovery, and per-wire rendering. These are hypotheses, not measured findings. The owning [roadmap slices](../roadmap/advanced.md#739-delivery-slices) require profiling before selecting optimizations.

**Benchmark design:** deterministic importable 50, 200 and 500 node fixtures, including connected oscillators, effects, modulation, sequencers, compact/expanded controls and realistic cable density. Record active canvas count, viewport-intersecting count, total recursive patch count, reachable DSP count, connection count, viewport size and zoom separately. Include dense layouts with approximately 200 nodes intersecting the viewport (respect 25–400% zoom; do not shrink UI below its allowed limits) and a larger graph with only a subset in view. Test the same fixtures with transport stopped and playing, monitor closed by default and plots closed/open in separate runs; use opt-in benchmark instrumentation or external browser profiling to measure overhead separately. Include import/time-to-interactive, idle, scripted drag, pan, pinch/wheel zoom, Fit, cable drag/selection, parameter edits, telemetry and nested navigation. Reproduce on a reference desktop and Android device; record exact revision, hardware, browser, refresh cadence, fixture fingerprint, warmup, sample count and configuration. Report repeated median/p95 frame gaps, observed FPS, long tasks, interaction-to-paint, component render counts, DOM/layout/paint cost, interop calls, allocation/GC and memory trend where available. Separate actual measurements from estimates and unavailable fields.

**Targets:** use the existing [cadence-relative health targets](performance-metrics.md#31-suggested-health-thresholds). On a 60 Hz reference, aim for 55–60 observed FPS and p95 frame gap below 20 ms during representative 200-node interaction, no repeated long tasks, no UI-induced audio interruptions and prompt input feedback; aim for usable 500-node interaction (at least 40 FPS and p95 at most 33 ms) and publish measured capacity rather than promising hardware-independent guarantees. Compare identical workload before/after; shared CI runner timings are diagnostic, not hard device-performance gates. Add deterministic regression assertions for render/invalidation scope, event coalescing, resource lifecycle, and graph/interaction correctness. Measure import/first paint separately from steady state.

**Preservation contract:** retain the shared root/nested canvas, original editable compact/expanded controls, all in-view nodes and individual input/output ports, selection, focus, drag, gestures, cables, anchor geometry, accessibility and state persistence. No automatic hiding of inactive nodes or changes to DSP/audio quality. Offscreen-only presentation culling may be evaluated with stable world geometry and overscan; retain logical visibility, graph membership, connection paths crossing the viewport, Fit and selection semantics. Never treat culling as a graph edit or interrupt audio. Keep telemetry throttling presentation-only, preserve accurate live effective values for expanded consumers, and maintain the existing on-demand performance-monitor lifecycle. Folded leaves retain editable base controls and no live readout or playback-driven rendering except explicitly pinned applicable modulated properties, as specified in [the expandable node contract](../editor/expandable-nodes.md). Prefer measured incremental improvements over a rewrite; evaluate alternative rendering technology only if traces justify it.

### Initial external editor benchmark tooling (7.3.9-S1, merged; baseline expansion merged)

[PR #125](https://github.com/wgabel/orbit2/pull/125) adds a distinct 50/200/500-node fixture recipe to the existing probe and reuses the published-app Chromium benchmark host. From the repository root after publishing the app and installing the browser dependencies described in [the DSP benchmark workflow](dsp-profiling.md#phase-734--benchmark-baseline-implemented):

```sh
dotnet run --project tests/Orbit.Audio.Probe/Orbit.Audio.Probe.csproj --configuration Release -- --editor-benchmark editor-benchmark-output
node scripts/benchmark-live.mjs --editor editor-benchmark-output editor-benchmark-output/editor-report.json editor-50 editor-200 editor-500
```

Set `ORBIT_PLAYWRIGHT_DIR`, `ORBIT_CHROME`, and optionally `ORBIT_BENCH_PUBLISH_DIR`, `ORBIT_REVISION` and `ORBIT_BENCH_HEADFUL=1` as for the existing live benchmark. Use `ORBIT_EDITOR_VIEWPORT=mobile` for a narrow emulated viewport (still mouse-driven, not physical Android or pinch), `ORBIT_EDITOR_PLAYBACK=0` for stopped-only profiling, `ORBIT_EDITOR_REPEATS=1..5` and `ORBIT_EDITOR_IDLE_MS=500..10000`. Default runs exercise stopped and playing idle, pan, wheel zoom and node drag three times. Preserve the generated patch files and their reported SHA-256 fingerprints; recipes have stable layout and parameters but fresh generated graph identities. CI generates and validates all three sizes via the real serializer/compiler, imports 50 nodes and measures both states; runner speed is diagnostic, not a timing gate. Compare identical saved fixtures, browser/viewport and settings before and after each optimization.

The report includes rendered/intersecting counts, wire count, zoom, pan, DOM elements, rAF frame gaps, long tasks where available, renderer CDP layout/style/script durations and heap delta. Import timing includes the import dialog lifecycle. Remaining S1 evidence includes physical desktop/Android measurements, true touch/pinch, explicit live control edits, Fit/cable/nested scenarios, component render counts, detailed traces and audio reliability measurements. Do not mark S1 complete or select a bottleneck from fixture counts alone. No runtime production instrumentation or audio changes.

**S1 baseline expansion (merged, [PR #127](https://github.com/wgabel/orbit2/pull/127)).** The initial [PR #125 build](https://github.com/wgabel/orbit2/actions/runs/45616217238) passed and imported the 50-node fixture with all 50 nodes intersecting the viewport and eight measured interaction windows. The new benchmark adds a reversible carrier frequency edit (normal compact base-value input, Enter commit, accepted playing revision check, original value restored). CI now attempts 50/200 desktop stopped and playing, 500 desktop stopped, and 200 narrow/mobile-emulated stopped; physical Android and 500-node playback remain explicit local workloads. Each measurement logs observed FPS, p95 callback gap, script/layout/style duration, long task count and visible/DOM counts alongside the JSON artifact. Missing metrics stay N/A. These numbers are not device capacity claims. The expanded [CI build](https://github.com/wgabel/orbit2/actions/runs/45619753000) passed; S1 remains partial because physical device and additional scenario evidence are still outstanding.

### S1 measured CI baseline and S2a node-frame isolation

Source: [PR #127 benchmark run](https://github.com/wgabel/orbit2/actions/runs/45619753000), headless Chromium, one repeat per workload, muted output, monitor closed, diagnostic runner timing. All 200 desktop nodes intersected the viewport; 40 of the same recipe intersected the narrow emulated viewport. The 500-node stopped desktop workload had 220 intersecting nodes. The measurements establish substantial UI-side interaction cost even with playback stopped, not a causal attribution to a single function or physical-device capacity.

| Desktop workload | 200 stopped FPS | 200 playing FPS | 500 stopped FPS |
| --- | ---: | ---: | ---: |
| Idle | 60.00 | 12.01 | 60.01 |
| Pan | 6.39 | 1.73 | 2.34 |
| Wheel zoom | 7.75 | 1.80 | 2.65 |
| Node drag | 7.33 | 2.54 | 4.07 |
| Parameter edit | 16.45 | 2.44 | 8.60 |

Stopped 200-node pan recorded 7460.43 ms cumulative script duration, 316.60 ms p95 frame gap, 27 long tasks and 26094 viewport DOM elements. These results justify incremental layout-only invalidation before broader changes. Preserve device baselines, traces, touch and remaining S1 coverage as follow-up rather than representing them as completed.

**S2a (merged, CI verified, [PR #128](https://github.com/wgabel/orbit2/pull/128)).** `GraphCanvas` caches ordered node/role projection against the immutable active graph snapshot. `NodeFrame` compares its last rendered visual inputs, preserving keyed children and their own interaction lifecycle, and renders conservatively while wire candidates are present or being cleared. Pending source is scoped to the owning node. Committed snapshot changes and shared telemetry still conservatively invalidate frames; S2b/S3 will address these separately. The explicit URL query `orbit-render-counts=1` enables per-frame DOM render counts; ordinary editor use does not increment counters or sample diagnostics. The benchmark's `ORBIT_EDITOR_RENDER_COUNTS=1` opt-in run asserts zero frame renders for stopped pan and only moved/previously selected frames for stopped drag. It records count deltas separately from ordinary timing runs. The [CI build](https://github.com/wgabel/orbit2/actions/runs/45622681151) passed, including stopped pan/drag render-count assertions; no audio or gesture behavior changes.

**S2a measured result.** On equivalent generated fixture recipes (separate CI runners, not identical saved GUIDs or physical-device measurements), 200-node stopped pan improved from 6.39 to 26.72 FPS, wheel zoom from 7.75 to 24.86 FPS, and drag from 7.33 to 19.69 FPS. Stopped pan cumulative script duration changed from 7460.43 to 1760.93 ms and p95 frame gap from 316.60 to 66.70 ms. Playing pan remains poor (2.16 FPS); do not infer that DSP is the only cause. Source: [PR #128 CI](https://github.com/wgabel/orbit2/actions/runs/45622681151).

**S2b (merged, CI verified, [PR #129](https://github.com/wgabel/orbit2/pull/129)).** `NodeFrameProjection` is a canvas-local presentation cache: compare equivalent immutable leaf snapshots across revisions (including parameter and port content, audition and record metadata), retain references only when equal, recompute node roles against the authoritative graph, scope estimated ranges to the owning node, and preserve range dictionary references only when all keys/values agree. Unknown (null) and absent ranges remain distinct. Replaced/removed nodes and canvas changes discard stale entries; composites remain conservatively invalidated rather than comparing nested graph internals. Graph commands, persistence, DSP and shared live effective values are untouched. Unit tests cover reuse, range invalidation, port/audition changes, composite revisions and reset; opted-in browser run asserts a stopped carrier frequency edit invalidates only that frame. The [CI build](https://github.com/wgabel/orbit2/actions/runs/45625609642) passed, including the single-frame stopped parameter-edit assertion.

**S2b measured result.** Equivalent 200-node fixture recipes on separate CI runs: stopped parameter-edit script duration 920.18 → 324.35 ms, observed FPS 17.68 → 21.74, p95 frame gap 533.20 → 233.30 ms. Playing pan remains 2.15 FPS; physical-device measurements and controlled identical-fixture comparisons remain outstanding. Source: [PR #129 CI](https://github.com/wgabel/orbit2/actions/runs/45625609642).

**S3a (merged, CI verified, [PR #130](https://github.com/wgabel/orbit2/pull/130)).** `NodeEffectiveValuesProjection` partitions each published active-canvas effective-value frame by node ID and preserves each read-only dictionary reference on exact key/value equality. Missing keys, missing nodes and empty/stopped frames clear prior values; resetting the canvas discards cached frames. No quantization, throttling, graph mutations or changes to the existing 40 ms playback observer, graph/revision filtering, DSP and transport rate. Expanded scope and envelope/playhead behavior remain unchanged. Unit tests cover reference reuse, independent updates, zero versus missing, reset and clearing. The opt-in 50-node browser count run now exercises playback, requires live effective readouts, asserts playing idle does not rerender every frame and checks that effective readouts clear on stop. Timing and test verification pending. S3b and S3c address remaining playhead/visualization and workspace publication work separately.

**S3b design amendment (planned, recorded in [PR #130](https://github.com/wgabel/orbit2/pull/130)).** Treat node expansion as a live-presentation consumer boundary shared with 6.21.5. Use the existing expansion state rather than a separate performance-mode toggle. An unpinned folded eligible leaf must not receive periodic effective values, playheads or animated visualization updates; a folded leaf with property pins receives only those applicable modulated values, never node-local animated plots merely because of a property pin; static base edits and all graph/layout-driven updates remain functional. No frozen effective reading. Expanded/pinned nodes resume current valid telemetry and configured plots. Independently active scope overlays, keyboard and monitor continue to receive the data they need; exempt full shells are not forcibly folded. Compare all-folded, one-expanded, and all-expanded (existing baseline) with the same patch and playback state; assert zero playback-telemetry-driven renders on folded leaf frames without pinned modulated properties after transition warmup, isolate updates to explicitly pinned applicable properties when folded, correct live values on expansion, bounded observation resources, and unchanged audio/graph behavior. S3c should avoid unnecessary canvas-wide publication when no consumer needs it. This is a planned contract change only; S3a runtime and its existing tests are unchanged.

**Property-pin amendment (planned, [PR #130](https://github.com/wgabel/orbit2/pull/130)).** [Expandable node contract](../editor/expandable-nodes.md) owns the UI and persistence rules. A per-property pin both overrides folded visibility and enables that property's live effective readout in folded mode, if applicable. Default-visible unpinned base editors remain editable and static when folded; expanded consumers retain normal live readings. Compare the unpinned all-folded workload against a few pinned modulated properties on the same patch; record node-frame and property-editor invalidation scope, active recipients and resource use, without altering DSP or ordinary graph editing. No runtime change in this documentation amendment.

**Composite-demand amendment (planned, [PR #130](https://github.com/wgabel/orbit2/pull/130)).** [Composite navigation and presentation boundary](../editor/composite-nodes.md) defines active-canvas ownership. The current `GraphWorkspace` already mounts a single graph-keyed `GraphCanvas` and selects its telemetry with `GraphParameterTelemetry.GetValues`; `FaustGraphPlaybackService.GetTelemetryAsync` nevertheless reads and maps meter outputs for the whole patch. Preserve the single mounted canvas and make active graph plus explicit consumer addresses the demand boundary. No node-local component, layout measurement, plot lease, playhead delivery, property projection or periodic refresh for inactive graph canvases, including parents, siblings and deeper closed children. Node/property pins never activate a closed graph; they restore eligibility only when its canvas is entered. Keep a parent composite shell's own exposed controls accurate when visible, including macro values without rendering its internal targets. Explicit independent consumers (armed performance keyboard, open supported scope, requested monitor) may receive only their required data even when another graph is active; do not reawaken a whole hidden canvas. Cache graph-qualified meter lookup/demand per accepted revision and subscription changes; avoid rebuilding recursive projections per tick. S3c first isolates consumer publication and lifecycle, S3d coalesces and filters nearer the telemetry read boundary, measuring output enumeration, transport and allocation savings separately; do not claim worklet-side savings if the existing backend still returns all meters. Preserve root DSP reachability, modulation, macro resolution, sequencer timing, transport synchronization, authoritative snapshots, layout persistence and actual audio samples. Switching canvas must not recompile, restart or mute audio. Validate graph/revision/generation and demand identity on asynchronous completion; clear stale displays, rebind current values on entry, release previous leases, handle stop, deletion and patch replacement. Benchmark a small root with a reachable 100-node child (including nested/sibling graphs), identical audio workload outside and inside; record active DOM/node counts, telemetry addresses requested/returned/delivered, render counts, leases, FPS/frame gaps, and audio continuity. Hidden canvas render/delivery counts must be zero; independently requested addresses are tracked separately. This is design only; no runtime or measured improvement in this amendment.
