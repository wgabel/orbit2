# Direct canvas connection amount slider

[Existing connection contract](annotations-and-connections.md) · [Roadmap](../roadmap/editor-and-effects.md#phase-619--patch-documentation-and-canvas-organization-partial-6195-core-and-6196-implemented) · [Interaction registry](user-interactions.md)

## Design (planned, not implemented)

**Owner decision — commit on release (Option A).** This is the current approved delivery scope. The slider previews its numerical value locally while moving; audio changes only when the edit is committed. Preserve compile-time constant coefficients and existing playback behavior. The earlier live-control investigation below is retained as historical evidence for a separate, deferred feature; it is not an implementation dependency.

The current cable badge selects the connection and opens an anchored amount editor; adjusting a value requires extra interaction. Make a normal horizontal range slider directly on the cable the primary amount control, with no popup, preliminary selection, or Apply button for ordinary slider edits. The existing inspector remains available for other connection actions and hidden/covered controls. Do not introduce a custom vertical-drag handle, knob, percentage-only representation, or a new connection parameter.

### Value contract

- Bind the slider to the same graph-qualified connection and its existing signed finite `SignalConnection.Amount`. Resolve the legal minimum, maximum, step/precision, default, formatting, unit and any existing display-scale mapping from the authoritative amount editor/validation and shared presentation helpers. Audit the source and tests first: do not infer a universal 0–1 or ±100% range, or reuse destination base-value bounds as modulation-depth bounds. If the current editor has no finite range or step, document that gap and obtain approval for a shared range policy before imposing a limit; preserve every existing legal amount and exact numeric entry.
- Reuse the normal shared slider styling and native range interaction; share value metadata with the existing amount editor rather than duplicate constants. Keep numeric values in actual units: direct parameter modulation uses the target unit; audio/intermediate routing uses a dimensionless multiplier. Preserve negative values, zero, unity and existing dormant semantics. A zero marker and signed fill may distinguish bipolar values; do not make color the only cue.
- Typed Trigger, Gate and Clock connections retain their unity event semantics and type badges; never show an adjustable amount slider where editing is not supported. Respect current active/dormant eligibility and validation.
- Show the current numerical amount above the rail. Clicking the value enables precise inline numeric entry on the canvas (Enter/blur commit valid values, Escape cancels, invalid/non-finite values do not mutate the graph). Reuse validation and formatting; keyboard range operations and accessible names/physical value text must work without capturing performance keys.

### Placement and visibility

Replace the numeric badge on eligible cables with a compact horizontal slider centered at the existing mathematical cubic Bézier midpoint. Reuse shared geometry and graph-local projection for root and nested canvases. Keep control dimensions and touch targets stable in screen space while the cable moves, pans or zooms; use existing theme tokens and connection colors. Preserve node and port positions, rigid sleeves, hit paths, cable selection, reconnection and context actions. No collision solver or manual slider positioning in the first version: sliders may overlap and remain behind nodes; covered controls can be accessed through normal cable selection/inspector.

In the default All connection-label mode, eligible sliders are directly visible without selecting cables. Preserve existing All/Modified/Selected/Off per-canvas visibility settings and event badges; in Off the inspector remains available. Do not introduce a second preference or silently change saved documents. Low-zoom automatic suppression is an existing optional refinement, not a prerequisite for the slider.

### Editing and runtime behavior

Pointer/touch/keyboard interaction with the standard rail must not open the inspector, pan the canvas, start a wire, select another edge, trigger long press, or count as a fit tap. A two-finger pinch retains universal navigation priority: cancel/restore incomplete edits without a history entry or loss of redo. Handle pointer cancellation, lost capture, deletion, graph changes and navigation safely; never write to stale graph-qualified IDs. Keep ordinary wire click/context actions outside the slider unchanged.

During pointer/touch adjustment keep a local presentation-only draft, with the number and rail updating immediately. Do not dispatch a graph command, publish a graph revision, update persistence/history, notify playback, or recompile on input/move. On successful pointer release commit at most one validated graph-qualified SetConnectionAmountCommand if the amount actually changed; the existing playback path may compile and replace the voice once for a reachable changed coefficient. There is no separate Apply button and no preliminary selection. Releasing without meaningful movement preserves an exact authored amount even when it falls between rail steps. A track tap is one edit. Keyboard range changes are one bounded gesture (preview on relevant keydown/repeat, commit on keyup or valid focus completion); do not stream repeated commits while a key is held. Escape, pinch takeover, pointer cancellation, unintended capture loss, stale identity or external conflicting changes discard the draft with no undo entry or playback operation. A late release after cancellation must be ignored. Use native range input events for local preview, but do not assume blur or change alone reliably identifies a successful pointer release; integrate with the existing gesture arbitration. Use the existing command and history path, not a separate history or audio transaction. Undo/redo, load/import and inspector changes refresh the rail from authoritative graph state. Preserve graph-local IDs, event exclusions, dormant behavior and literal coefficients; do not modify Faust source generation, topology comparison, runtime control manifests, smoothing, worklet lifetime or replacement scheduling for this feature. Keep preview state in the affected slider rather than causing unrelated node/canvas rerenders; no new per-edge telemetry or polling. Audio stays at the last committed amount during preview; existing replacement/crossfade behavior after release is unchanged.

### Verification and integration

Test the actual metadata/range/step/unit and round-trip for supported connection categories, signed/zero values, event-only exclusions, precise numeric entry and invalid input; compare slider and inspector edits and verify save/load and undo/redo. Test midpoint positioning and constant screen size on zoom/pan/node movement, overlapping/hidden sliders and nested canvases. Cover mouse, touch, keyboard, pinch cancellation, context actions, wire drag and performance-key isolation in published browser tests. Exercise stopped and active playback: prove zero graph revisions/history entries/source builds/voice replacements during preview or cancellation, and at most one commit and one existing compile/replacement request for a changed release; a stopped edit must not start playback. Measure representative dense-patch drag responsiveness and report physical-device limitations. Update actual usage and the interaction registry when behavior ships. Keep the view model renderer-independent for the planned GPU editor; no GPU migration is required for this feature.

## S1 contract audit — existing source evidence

Inspected at `d59f0ac3fdf4298c2b264f68e8e0318216f6bb25`. `SignalGraphValidator.ValidateConnectionAmount` accepts every finite signed coefficient for ordinary connections and requires exactly 1 for event types. `ConnectionAmountEditor.razor` uses `type="number" step="any"` without min/max; the code-behind parses a finite double and dispatches the graph-qualified command. A destination parameter's base range/display scale is not a coefficient range. Therefore **there is no existing slider interval or step to reuse**. Preserve this graph validation. A proposed finite *display-only* range (e.g. symmetric around zero, with unit-aware defaults and expansion for the current amount) must be agreed before choosing rail limits and precision. Exact input must remain available outside the display range.

`GraphWorkspace.DispatchConnectionCommand` currently requires selection; direct edits need an independent graph-qualified command entry with stale-edge protection. Existing parameter gestures have a coalesced history path and pinch rollback; do not assume that cancellation also supports connection edits without tests.

`GraphTopology.Matches` compares full connection records, including Amount; `FaustGraphPlaybackService.UpdateAsync` compiles on topology mismatch and replaces the voice when generated source differs. Existing `ConnectionAmountCommandTests` assert the literal coefficient changes in generated Faust source. The selected amount editor explicitly uses Apply to avoid repeated compilation. **Do not stream amount commands during a drag on this runtime path.** A safe realtime path requires a reviewed separate design and regression baseline under [the audio optimization gate](../quality/audio-engine-optimization.md): stable graph-qualified controls, smoothing/zero handling, composite flattening, stale generation and DSP state continuity. No audio runtime modification or measurements have been made in S1.

The shared renderer-neutral `ConnectionAmountSemantics` projection is introduced for the existing badge/editor to resolve target parameter, destination type and event eligibility consistently, without changing validation or user-facing behavior. The adaptive display policy was implemented in S1a; realtime control work is no longer a dependency for S2 under the owner's Option A decision. Published smoke tests currently select the badge and inspect the popup; preserve their acceptance intent when replacing the control.

## S1 display-only rail policy

The renderer-independent `ConnectionAmountSliderRange` provides a provisional, tunable display policy, not new domain limits. All ordinary amounts remain valid if finite; typed events have no rail. The normal horizontal rail is linear and bipolar, with zero at the midpoint. Initial preferred extents by receiving parameter unit are ±200 Hz, ±1200 cents, ±24 dB, ±2 s, ±360 degrees, ±120 BPM, ±1000 ms, ±12 semitones, and ±2 for normalized, ratio, audio or intermediate coefficients. These are UI defaults selected for practical editing, not limits derived from parameter base values; tune them after usage feedback.

Resolve a symmetric extent covering the actual amount. Outside the preferred extent use twice its absolute magnitude when representable (otherwise use the finite double maximum). Represent the native range internally as −1…+1 with step 0.01 (200 intervals), mapping linearly to actual coefficient units; label and accessible text must show the physical amount rather than normalized position. Using normalized coordinates avoids overflow in the physical span for extreme saved values. Do not quantize or write a committed amount just because its existing precise value lies between rail steps. Numeric entry and the existing inspector preserve the exact authored coefficient.

Capture the extent for an edit and retain it across all events in that gesture. Keep the existing extent after a successful edit while the new value remains inside it; recalculate on graph/connection identity changes or external amounts outside the current extent. No new persisted field, no graph change for resolving a rail, and no display-only change to audio. A future slider may adjust these default extents based on evidence; no runtime behavior changes in this slice.

The approved commit-on-release design uses this provisional display policy without requiring live playback changes. Do not wire continuous edits to the current compilation path. No new audio production changes are authorized.

### Existing source trace

- `FaustGraphCompiler.Compile` calls `GraphFlattener.Flatten`, which resolves effective macro bases and maps root and child edges to flattened IDs. It removes dormant destinations while retaining authored edges in the graph. `GraphDependencyOrder` orders reachable nodes. `FaustNodeContext.InputSignal` emits signed literal multipliers for ordinary incoming edges and enforces a single unity source for event inputs. Literal zero can permit compiler elimination; a dynamic zero may keep upstream computation alive. Its cost and sound continuity require measurement.
- `FaustGraphCompiler.InputIdentity` aliases a unity single incoming signal to its upstream observation identity, and boundary output aliases propagate this identity. A coefficient change from unity alters this relationship. Dynamic taps use the resulting observation catalog and selectors; simply ignoring Amount in topology comparison would leave stale tap identities. `SignalTapManifest` distinguishes the dynamic observation IDs from fixed channels. Any live path must keep weighted receiving signals independent of the raw source at every amount, including unity, and preserve legitimate aliases through transparent boundaries.
- `FaustGraphProgram.InitialControlValues` collects parameter and audition manifests; `FaustGraphPlaybackService.GetControlValues` reads current values from the immutable graph and `GraphTopology.Matches` includes full connection records. `ActiveGraphPlayback` holds the accepted generation, topology, manifest and value map. Each request announces its revision before the update lock; stale requests are skipped. A changed source calls `ReplaceAsync` with a new generation, otherwise the existing batched `SetGraphControlsAsync` path updates values and patterns. A successful acceptance updates snapshot and revision; telemetry requires matching revision and generation. These paths run per graph revision, not per DSP sample.
- Browser `FaustNodeFactory` resolves unique parameter suffixes against the worklet's `getParams()`, validates finite values before writes, tolerates optimized-away manifest controls for that voice, and uses `setParamValue`. JavaScript double finiteness alone is not a guarantee of representability in the generated Faust control or audio precision. Inspect real generated WASM and control metadata before selecting ranges or conversions.

### Candidate: graph-qualified live coefficient controls

1. Preserve authored graph validation, identity, persistence, history and existing event unity. Add a dedicated connection-control manifest entry for each reachable, active, editable ordinary edge, containing original owning graph ID, edge ID, stable backend name, and initial value. Extend flattening with edge-origin mapping; never infer original IDs from generated hashes. Do not treat this as a node parameter or an extra port. A zero coefficient remains editable and is not a mute; dormant/unreachable edges have no live control and must be restored correctly when reactivated.
2. Emit a stable coefficient control expression wherever a live-eligible ordinary edge is multiplied, with canonical source ordering and metadata independent of its current eligible amount. Keep event routes literal and exclude them from live controls. Reuse the same weighted expression for master, parameter fan-in, rack boundaries and observation; only alias truly invariant unity paths. An eligible weighted input must retain a separate identity even at unity so its observation selector stays valid across edits. Quantify selector/catalog growth and validate the existing bounded slot policy.
3. Reuse the existing host value batch and generation/revision acceptance path; include connection controls in initial and replacement values, and resolve them by graph-qualified edge ID for live updates. Classify amount-only changes as reusable only for a proven eligible manifest and compatible observation topology; structural edits, reactivation and nonrepresentable values keep a validated replacement fallback. Never suppress recompilation simply because endpoints match. Review startup/stop and in-flight replacement, newer revisions and rejected updates. Do not schedule individual updates per DSP sample or send UI-side LFO samples.
4. Choose numeric encoding after inspecting the pinned compiler and host. The display rail must never become the DSP bound. Preserve exact committed values in the model; establish finite representable control range, precision/tolerance and a fallback for legacy outliers before enabling. No silent clamp or conversion to infinity. For sound, assess control-rate step behavior versus smoothing at amplitude/modulation coefficient changes. Static initial values must not fade from zero or alter attack/phase. A deliberate ramp is a transient behavior change and requires owner review; do not blindly reuse parameter smoothing. At rest target static equivalence at both supported sample rates, and no new discontinuities, note resets, loss of effect tails or event drift during live updates. Keep existing literal path until the candidate passes the gate.
5. The alternative is a standard rail with a local preview and one explicit commit on release, using existing recompilation. This is cheaper to implement but does not deliver audible real-time adjustment. The owner has now explicitly chosen this alternative; it supersedes the earlier live-first design.

## S2a — Local draft and guarded commit boundary

The renderer-neutral `ConnectionAmountDraft` owns one gesture's original edge, workspace generation, graph identity, retained rail extent and preview amount. It cannot access the patch session, history or playback. Native position input only updates the draft; cancellation is terminal; completion produces at most one `ConnectionAmountCommit` with the original immutable edge and changed amount. The workspace must validate that request against the current active graph and workspace generation immediately before dispatching its existing command. If the edge disappeared or its endpoints/amount changed, or the destination is no longer editable, reject it. Observe authoritative changes during the gesture to invalidate pending input. Returning to the original snapped thumb position preserves an exact between-step authored value. Retain the chosen range only for the same graph/edge and compatible semantics. Tests exercise normal commit/undo/redo, no mutation during preview, cancellation with existing redo, conflict and removal, replaced workspace and nested canvas ownership. No visible rail or input adapter is connected in this slice; S2b supplies that wiring and browser gesture tests. Existing inspector and audio behavior are unchanged.
